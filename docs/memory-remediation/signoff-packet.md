## 2. 联动约束（**S2 与 S3 必须一起签，不得分开**）

理由：注入侧过滤**依赖指纹存在**；指纹被截断 = 过滤失效 → 决策二直接决定决策一的安全承诺是否成立。

### 合法组合矩阵

| 决策一 | 决策二必须选 | 说明 |
|---|---|---|
| **A（归档排除）** | **① 或 ②**（③ 不充分） | 快照不再携带记忆，但**会话转录仍可能含文本** → 截断后仍可被召回；故必须解决截断。③"先归档排除再允许截断"不成立 |
| **C（注入侧 + UI 侧覆盖）** | **① 或 ②（强烈建议 ②）** | 本组合下**注入侧是唯一防线**：指纹一旦被截断，已删文本立即重新可注入 → 决策二不可缺省 |
| **B（恢复过滤，已不推荐）** | ① 或 ② | 若仍选 B，截断问题同样存在 |

**不允许的组合**：决策一选 A/C 而决策二选"③ 允许截断且不解决"——这等于接受"删除不可复活"在长周期上失效。

### 推荐组合

**决策一 = C（不做 B）+ 决策二 = ②（取消丢最旧、改按大小告警）**
- C：prompt 级安全已闭环（learnings / session-recall 已按指纹过滤，只读侧排除、不改数据）；剩余为磁盘/UI 层可见性，由 UI 批处理；
- ②：撤销记录是安全账本，静默丢弃与"删除不可复活"冲突；增长成本可忽略（约 40B/条，5000 条 ≈ 200KB）。
- 若产品希望"记忆是独立资产、不随回滚" → 另选 **A**，但 **决策二仍须选 ①②之一**。
