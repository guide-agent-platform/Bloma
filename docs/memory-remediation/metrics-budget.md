## 2. 撤销名单的读频率（为何不加缓存）

`prepareRecallBlock` 有**指代词门控**：任务不含 `上次|上回|之前|先前|继续` 时**直接返回 null，连文件都不读**。因此实际读频率比"每次召回"还低一档 = **"触发的召回才读"**；learnings 侧为每轮 loop 渲染一次。

**因此不加缓存/防抖**（反例存档，供将来讨论时直接引用）：
- **缓存 TTL = 删除生效延迟 = 复活窗口** —— 与 fail-closed 目标直接冲突（安全控制不应引入陈旧窗口）；
- 读频率已是任务级、且低于每次任务（含门控），相对第 2 项（会话索引全量 ~1.0s）是零头；
- 收敛点：§11 契约 `renderMemory()` —— **一次读取、多出口复用**（届时第 5 处的读次数进一步下降）。

## 3. 失败语义（与总原则一致）

| 场景 | 行为 |
|---|---|
| 任意记忆层 IO 异常 | **生成主链 fail-open**（不阻断生成） |
| 注入侧读不出数据 / 名单不可读 | **注入侧 fail-closed**（该层整体不注入） |
| sidecar（埋点）损坏 | 只影响 UI 显示，**不影响注入** |

## 4. 度量口径（算法与基线 → S-5 填数值）

| 指标 | 口径定义 | 基线 | 目标值 |
|---|---|---|---|
| 召回命中率 | 触发的召回中，用户在后续轮次实际复用/确认历史内容的比例（人工标注或行为代理） | 待 S-5 | 待批准 |
| 召回误报率 | 注入片段与当前任务无关的比例（人工抽检） | 待 S-5 | 待批准 |
| 撤销生效延迟 | 删除动作 → 各注入面不再出现该文本的最大轮次/时间差 | **0（无缓存）** | 保持 0 |
| 成本 | 记忆相关 LLM 调用增量（当前：0，零 LLM 主路） | 0 | 保持 0 |
| 延迟 | 上述 5 处 IO 的 p50/p95 | 待 S-5 实测 | 待批准 |

## 5. 与 `whitespace-values.md` 的关系

本文件定义**清单、口径与失败语义**；`whitespace-values.md`（S-5）负责**具体数值**（各层条数/字符上限、指纹上限、召回阈值、成本与延迟目标）。两者交叉引用，**不重复记数**；数值变更只改一处并在另一处留指针。
