## §2 权限门 — `main/permission-service.ts`

**内部状态**：`pendingRequests: Map<request_id, {resolve, request}>`（决策挂起表）、
`sessionIndex: Map<session_id, Set<request_id>>`（会话维度索引）、全局 `globalPermissionMode`（默认 `ask`）、
单例 `requestPublisher`。

**关键常量**：`TOOL_PERMISSION_REGISTRY`（`permission-service.ts:132`）——工具分级唯一权威登记点
（Read/Glob/Grep/read_file 等只读 `safe`；Write/Edit/web_fetch/write_file/run_preview/create_snapshot/
run_project 等 `warning`；`rollback_snapshot` `dangerous`）。命令类工具（Bash/run_project）登记为
warning，但命中危险命令模式（`rm -rf`/`sudo`/`format`）升级为 dangerous（`assessDanger`:185）。

### 2.1 canUseTool — `main/permission-service.ts:65`（详细级）

- **输入**：`toolName`、`toolInput`、`sessionId`、`currentMode: PromaPermissionMode`、`projectId?`
- **副作用**：决策请求入 `pendingRequests`（ask 模式）+ 调 `requestPublisher`（渲染端弹权限卡）；
  `resolvePermission` 回传时从挂起表移除
- **返回值**：`PermissionResult {behavior:'allow'|'deny', updatedInput?, updatedPermissionMode?}`
- **决策表**：

| 危险度 | ask | allow-all | safe |
|---|---|---|---|
| safe | allow | allow | allow |
| warning | **弹卡待决**（异步 resolve） | allow | deny |
| dangerous | **弹卡待决** | **deny**（自动化不弹卡） | deny |

```text
canUseTool(toolName, toolInput, sessionId, currentMode, projectId):
  dangerLevel = assessDanger(toolName, toolInput)          # safe/warning/dangerous
  if dangerLevel == 'safe': return {behavior:'allow'}
  if currentMode == 'allow-all' and dangerLevel != 'dangerous':
    return {behavior:'allow'}                              # 自动化管线：warning 自动放行
  if currentMode == 'safe': return {behavior:'deny'}       # 保守模式：非 safe 一律拒绝

  # ask 模式（用户显式操作）：进挂起表，等渲染端决策回传
  request = { id: randomUUID(), session_id, project_id, tool_name, tool_input,
              danger_level, user_visible_summary: summarizeToolRequest(toolName, dangerLevel),
              created_at: now }
  return new Promise((resolve) => {
    pendingRequests.set(request.id, {resolve, request})
    sessionIndex 记录 request.id
    requestPublisher?.(request)                            # → 渲染端弹权限对话框
  })
  # resolvePermission 命中该 request_id 时 resolve({behavior: input.decision})
```

> **注意**：`canUseTool` 在 ask 模式返回的 Promise 可能永不 settle（用户不决策）。Agent Loop 的
> `executeToolCall` 用 `withAbort` 与其竞速（见 03 §2.1），且 loop 恒传 `allow-all`，非 allow-all
> 直接拒绝进 is_error——避免 ask 模式挂起死循环。

### 2.2 权限接线与决策回传（摘要）

- `assertToolAllowed`（`permission-service.ts:54`）— 生产接线入口（A2-12）：内部工具/IPC 通道执行前调用，
  denied 时抛 `PERMISSION_DENIED:<toolName>`；无人值守管线显式传 `allow-all` 豁免 UI 弹窗。
- `resolvePermission`（`permission-service.ts:98`）— IPC `permission:resolve` 服务侧：按 request_id +

  `PERMISSION_REQUEST_NOT_FOUND`。
- `allowAutomatedTool`（**实际位于** `programming-orchestrator.ts:1607`，不在本文件）— 无人值守自动化管线的
  权限门薄封装：`await assertToolAllowed(toolName, toolInput, sessionId, AUTOMATED_PERMISSION_MODE, projectId)`。
  `AUTOMATED_PERMISSION_MODE = 'allow-all'`（`programming-orchestrator.ts:37`）。runSketchTask/runMvpTask/

  > ⚠ 锚点澄清：`allowAutomatedTool` 不在 `permission-service.ts`——本文件的接线入口是 `assertToolAllowed`（:54）。
- `setPermissionRequestPublisher`（`permission-service.ts:23`）— 注入渲染端弹卡发布器（index.ts 接线）。
- `getPermissionMode` / `setPermissionMode`（`permission-service.ts:36` / `:41`）— 全局权限模式

## §3 CSP 与网络出口防护

### 3.1 MAIN_FRAME_CSP — `main/csp.ts:13`

```text
MAIN_FRAME_CSP = "default-src 'none';
                  script-src 'self';
                  style-src 'self' 'unsafe-inline';
                  img-src 'self' data: blob:;
                  font-src 'self';
                  connect-src 'self' http://localhost:* https://api.anthropic.com;
                  frame-src 'self' http://localhost:* http://127.0.0.1:*"
```

- **约束**：仅对 `mainFrame` 注入（`shouldInjectMainFrameCsp`:27，resourceType === 'mainFrame'）；子帧交给
  沙箱静态服务器自身的 CSP——否则主窗 `script-src 'self'`（无 unsafe-inline）会与沙箱 CSP 取交集，把生成页
  内联 `<script>` 整段屏蔽（「渲染不出 UI」）。
- `frame-src` 只放开本地回环（localhost/127.0.0.1）任意端口，不放任何外部 origin。
- `connect-src` 允许 LLM 渠道（api.anthropic.com）+ 本地沙箱预览。

### 3.2 assertPublicHttpUrl — `main/net-guard.ts:23`（详细级，web_fetch 与向导市调共用）

- **输入**：`raw` URL 字符串；**返回值**：`{ok:true, url:URL} | {ok:false, error}`（SSRF 防护，v1 静态判定）
- **降级链**：判定失败 → web_fetch 工具返回 is_error 让模型换地址/自纠（不崩循环）

```text
assertPublicHttpUrl(raw):
  try: url = new URL(raw)
  catch: return {ok:false, error:'URL 无效：raw'}
  if protocol not in (http:, https:): return {ok:false, error:'只允许 http/https 地址'}
  host = url.hostname 去括号小写
  if !host.includes('.') and !host.includes(':'):
    return {ok:false, error:'非常规主机名不允许抓取（无点主机名挡内网单标签名/IP 编码）'}
  if host == 'localhost' or 以 .localhost/.local/.internal 结尾:
    return {ok:false, error:'内网/本机地址不允许抓取'}
  if isDisallowedIpLiteral(host): return {ok:false, error:'内网/保留地址不允许抓取'}
  return {ok:true, url}
```

> **已知边界（明示不静默）**：v1 静态判定不做 DNS 解析复核（DNS rebinding 不防），桌面端模型半信任场景
> 够用；未来接入不可信内容源须升级为解析后复核。
> `isDisallowedIpLiteral`（`net-guard.ts:47`）：IPv4 段式判定（0/10/127、169.254、172.16-31、192.168、
> ≥224 组播/保留）+ IPv6 前缀式（`::1`/`::`、`fc00::/7`、`fe80::/10`）。
> `htmlToText`（`net-guard.ts:69`）：零依赖 HTML→纯文本（去脚本/样式/注释→块级换行→剥标签→解码实体），
> 行内格式标签直接剥除不加空格（中文无词间空格语义）。常量：`NET_FETCH_TIMEOUT_MS=15s`、`MAX_BYTES=2MB`、
> `DEFAULT_CHARS=12000`、`MAX_CHARS_LIMIT=50000`（`net-guard.ts:12`）。

## §4 OWASP 静态扫描 — `main/security-scan.ts`

### 4.1 runSecurityScan — `main/security-scan.ts:113`（详细级）

- **输入**：`SecurityScanInput {project_id, root_path}`
- **副作用**：只读扫描，不改产物；`passed=false` 由调用方接入 security_error 修复循环（见 01 §7.1，
  Agent Loop 路径只终验不重修）
- **返回值**：`SecurityScanResult {passed, issues: SecurityIssue[], scanned_files}`；
  `passed = 无 high/critical`（low/medium 只记录不阻断）

```text
runSecurityScan({project_id, root_path}):
  files = collectFiles(root_path)      # 递归收集 .html/.htm/.js/.mjs/.cjs/.ts/.jsx/.tsx/.css
                                        # 跳过 node_modules/.git/dist/dist-main（:95）
  issues = []
  for file in files:
    content = readFileSync(file)       # 读失败跳过
    for line, index in content.lines:
      for rule in SCAN_RULES:          # 按严重度从高到低排列
        if rule.pattern.test(line):
          issues.push({severity, category, user_visible_summary, file: 相对路径, line: index+1})
          break                        # 同一行命中首个规则即止（避免重复上报）
  passed = !issues 存在 severity ∈ {high, critical}
  return {passed, issues, scanned_files: files.length}
```

> **规则集**（`SCAN_RULES`:56，按严重度降序）：
> `dangerous_execution`（critical）— `eval(`/`new Function(`/`document.write(`；
> `sensitive_data`（high）— `api_key|password|secret|token` 等硬编码 `[:=] "值"`（≥4 字符）；
> `unsafe_dom`（high）— `innerHTML = 非字符串`（`[^\s"']` 判据避开静态字符串误报）；
> `inline_event_handler`（medium）— `onclick|onerror|onload` 等内联处理器；
> `insecure_resource`（low）— `src/href/url = "http://"`。
> **面向用户摘要不含 XSS/SQL 注入等技术术语**（self-healing-judge @S2-JUDGE-008）。
> `renderSecurityScanMarkdown`（`security-scan.ts:156`）— 渲染安全扫描报告写 documents/security-scan.md。

### 5.1 runSandbox — `main/platform-services.ts:63`（详细级）

- **输入**：`SandboxRunInput {request_id, project_id, command?, timeout_ms?}`
- **副作用**：spawn 沙箱子进程、写入 `activeSandboxes`/`sandboxLogs`、`waitForSandbox` 探活、失败分类
- **返回值**：`SandboxRunResult {status:'running'|'failed', preview_url?, port?, error_summary?}`
- **幂等语义**：同一 project 已 running 且健康时**直接复用**（不 stop 不 spawn）；崩溃/挂起时 map 已被
  exit 清理或 healthCheck 失败 → 照常 stop+spawn 重启

```text
runSandbox(input):
  project = findProject(input.project_id)
  # ---- 幂等守卫：同 command 已运行且健康 → 复用，消除冗余重启（preview_url 抖动）----
  existing = activeSandboxes.get(project_id)
  if existing and existing.command == input.command and healthCheck(`http://localhost:${existing.port}`):
    return {status:'running', preview_url, port}

  await stopSandbox({project_id});  sandboxLogs.set(project_id, '')
  for attempt in 0..MAX_PORT_ATTEMPTS-1:
    port = await findAvailablePort(3000, 3999);  previewUrl = `http://localhost:${port}`
    child = sandboxProcessFactory(root, port, command)     # 命令沙箱 / 内嵌静态服务器
    activeSandboxes.set(project_id, {process:child, port, command})
    捕获 child.stdout/stderr → sandboxLogs（供修复循环，不向 P0 展示堆栈）
    started = await waitForSandbox(child, previewUrl, timeoutMs)   # 探活（§5.2）
    if started.ok:
      child.once('exit', 清理 activeSandboxes 若仍是本进程)
      return {status:'running', preview_url: previewUrl, port}
    child.kill(); activeSandboxes.delete(project_id)
    if started.category != 'port_unavailable':
      return {status:'failed', error_summary: classifySandboxFailure(category, logs)}
  return {status:'failed', error_summary: classifySandboxFailure('port_unavailable','')}
```

> `spawnStaticServer`（`platform-services.ts:200`）：显式命令仅允许 `ALLOWED_SANDBOX_COMMANDS`
> （`npm run dev`/`npm start`/`node static-server`，越界抛 `SANDBOX_COMMAND_NOT_ALLOWED`）；Windows 下
> npm 为 npm.cmd 需 `shell:true` 包装并标 `treeKillWin32`（整树击杀）。内嵌脚本 cwd 落在系统临时目录
> （避免 Windows 进程 cwd 锁住项目目录，回滚 rmSync EBUSY 根因）；脚本自带 CSP
> `default-src 'self'; script-src 'self' 'unsafe-inline'; connect-src 'none'; …`（`STATIC_SERVER_SCRIPT`:300，
> 生成代码不得联网，`script-src` 已收紧去掉 unsafe-eval）。

### 5.2 沙箱生命周期（摘要）

- `waitForSandbox`（`platform-services.ts:170`）— 探活：监听 exit/error（EADDRINUSE → `port_unavailable`

### 6.1 handleAgentStreamEvent — `main/notifications.ts:97`（详细级）

- **输入**：`event: AgentEvent`（主进程事件流，index.ts 接线）
- **副作用**：即时系统通知（completed/error/user_decision_required/sketch_ready/mvp_ready）；`stage_changed`
  离开阻塞态时清待决策提醒状态
- **降级链**：无 project_id 直接忽略；AGENT_CANCELLED 不打扰（用户主动停止不是失败）；`findProject` 失败
  用兜底文案不挂通知链路

```text
handleAgentStreamEvent(event):
  if !event.project_id: return
  switch event.type:
    'completed':
      # completed 是通用终态（引导澄清轮次也会发）：只对「真完成」（当前阶段 ready/completed）通知
      stage = findProject(project_id).current_stage   # catch → ''
      if stage ∈ {ready, completed}: notifyTaskCompleted('生成和测试都跑完了…')
    'error':
      if payload.code == 'AGENT_CANCELLED': break      # 用户主动停止，不是失败
      handleFailed(project_id, payload.message)        # 「出问题了」+ onClick 聚焦
    'sketch_ready':  notifyTaskCompleted('草图已经画好了…确认后我继续做 MVP')
    'mvp_ready':     notifyTaskCompleted('MVP 已经生成好了…')
    'user_decision_required':
      showSystem('需要你决策', title, onClick:聚焦, onDismiss: markPendingDecisionIgnored)
      lastNotifiedAt.set(project_id, now)              # 待决策轮询频率上限从这次通知算起
    'stage_changed':
      if stage != 'blocked_for_user_decision': clearProjectReminderState(project_id)   # 脱离阻塞，清状态
```

### 6.2 scanPendingDecisionsForReminder — `main/notifications.ts:201`（详细级，待决策不沉底）

- **输入**：`now`（时间戳）；**返回值**：`PendingDecisionScanResult {notified, pending, skippedFocused, skippedIgnored}`
- **持久依据**：项目存储 `current_stage === 'blocked_for_user_decision'`（切项目/重启都找得回）
- **降级链**：窗口聚焦跳过（用户正看着决策卡，不推进时间戳——失焦后立刻能提醒）；用户显式忽略（关闭
  通知）后该项目不再提醒，直到脱离阻塞态；轮询异常不崩应用（定时器 catch 下轮重试）

```text
scanPendingDecisionsForReminder(now):
  pending = listProjects('active') where current_stage == 'blocked_for_user_decision'
  pendingIds = set(pending.project_id)
  # 清理已脱离阻塞项目的旧状态（忽略标记/时间戳），保证新一轮阻塞能重新提醒
  lastNotifiedAt / ignored 中不在 pendingIds 的 key 删除

  for project in pending:
    if ignored.has(project_id): skippedIgnored += ; continue
    last = lastNotifiedAt.get(project_id)
    if last != undefined and now - last < reminderIntervalMs: continue     # 频率上限
    if isWindowFocused(): skippedFocused += ; continue                    # 聚焦不推时间戳
    lastNotifiedAt.set(project_id, now)
    showSystem('还在等你决策', blockedDecisionBody(project.blocked_action),
               onClick:聚焦, onDismiss: markPendingDecisionIgnored)
    notified += project_id
  return {notified, pending: [...pendingIds], skippedFocused, skippedIgnored}
```

> `blockedDecisionBody`（`notifications.ts:243`）— 按 `blocked_action`（mvp_repair/test_repair/judge_return/
> security_repair）给差异化文案；`markPendingDecisionIgnored`（:259）— 显式忽略（同项目不再反复提醒）；
> `startPendingDecisionReminderLoop`（:284）— 生产由 index.ts 启动的轮询定时器（异常 catch 不崩应用）；
> `setNotificationBackend`/`setWindowFocusedHook`/`setFocusWindowAction`（:49/:53/:57）— 依赖注入 seam。

### 8.2 configureContentSecurity — `main/index.ts:150`（详细级，CSP 注入的收窄关键）

- **输入**：`BrowserWindow`；**副作用**：`session.defaultSession.webRequest.onHeadersReceived` 钩子
- **关键陷阱**：必须按 `resourceType === 'mainFrame'` 收窄——onHeadersReceived 拦截 session 内**所有**
  请求，不收窄会把主窗 CSP 一并注入沙箱 iframe 的 index.html 响应，主窗 `script-src 'self'`（无
  unsafe-inline）与沙箱自身 CSP 取交集，把生成页内联 `<script>`（给 `.screen` 加 `.active`）整段屏蔽，
  导致「沙箱里渲染不出应有的 UI」

```text
configureContentSecurity(window):
  session.defaultSession.webRequest.onHeadersReceived((details, callback):
    if !shouldInjectMainFrameCsp(details.resourceType):
      callback({responseHeaders: details.responseHeaders})    # iframe/脚本/样式不动，交给各自响应 CSP
      return
    callback({responseHeaders: {...details.responseHeaders,
                                 'Content-Security-Policy': [MAIN_FRAME_CSP]}})
  # frame-src 允许主窗 iframe 加载沙箱预览（localhost），否则 default-src 'none' 把 iframe 一并禁掉
```

### 8.3 configureOutboundAllowlist — `main/index.ts:173`（详细级）

- **输入**：无；**副作用**：`onBeforeRequest` 钩子，拦截非白名单主机的出站请求（防生成代码外泄数据或 SSRF）
- **白名单**：`ALLOWED_OUTBOUND_HOSTS = {localhost, 127.0.0.1, api.anthropic.com}`（:167）
- **降级链**：dev 模式（未打包）跳过拦截（Vite HMR websocket 等）；URL 无法解析放行（file:// 或自定义协议）

```text
configureOutboundAllowlist():
  session.defaultSession.webRequest.onBeforeRequest((details, callback):
    if !app.isPackaged: return callback({cancel:false})      # dev 模式跳过（Vite HMR 等）
    try:
      hostname = new URL(details.url).hostname
      callback({cancel: !ALLOWED_OUTBOUND_HOSTS.has(hostname)})
    catch:
      callback({cancel:false})                                # 无法解析放行
```
