## 1. 实验目的

孙浩原主观认为「完整 PRD 信息有用性存疑」，周大成要求用实验数据说话，不能凭主观。本实验验证：**用户侧输入形态（一句话 / 简单 / 完整）对 PRD 产出信息密度与可验收性的实际影响**。

## 2. 实验设计（同等环境控制）

| 控制项 | 取值 |
|---|---|
| 需求主题 | 学习笔记应用（胡昊老师建议的演示级用例） |
| 模型 | `deepseek-v4-pro`（本机 bloma-channels.json 唯一启用渠道，固定不变） |
| 生产管线 | `generatePrdLlm`（prd-engine-llm.ts）+ `anthropicMessagesQuery`（orchestrator.ts）——**不复制提示词**，与线上同构 |
| few-shot 注入 | 注入点③开（`template_type=personal_tool`，同类型脱敏样例） |
| 温度 | 0.1（prd 类别缺省） |
| 每形态重复 | 3 轮（`BLOMA_EXPERIMENT_RUNS=3`） |

**三形态唯一变量 = 用户侧输入**（会话内容 + 功能项颗粒度）：

| 形态 | 会话输入 | 功能项 |
|---|---|---|
| A 一句话 | 「帮我做一个学习笔记应用。」 | 1 条裸功能项 |
| B 简单 | 4 条要点 | 4 条裸功能项 |
| C 完整 | 结构化 PRD 文本（定位/功能+验收/范围外/约束） | 4 条带 story+行为断言+优先级+范围外 |

## 3. 结果（3 轮均值）

| 度量 | A 一句话 | B 简单 | C 完整 |
|---|---|---|---|
| 成功 | 3/3 | 3/3 | 3/3 |
| 验收总字数 | **78** | **367** | **258** |
| EARS 可测性命中 | **1.0** | **5.3** | **3.7** |
| 范围外条数 | 0 | 0 | **3** |
| 假设条数 | 3 | 4 | 3.3 |
| 锚点保真 | true | true | true |
| 平均耗时 | 3.2s | 7.8s | 4.6s |

## 4. 结论

1. **一句话 → 简单是决定性跃升**：验收信息密度 78→367 字（≈4.7×）、EARS 可测性命中 1→5.3（≈5×）。一句话形态产出的 PRD 几乎不可验收（EARS 仅 1 次命中、零范围外约束）——**数据支持导师「一句话需求几乎必出 major」的判断**（呼应待拍板项 D1）。
2. **简单 → 完整不升反降**：验收字数 367→258（≈-30%）、EARS 5.3→3.7。原因：完整形态的验收细节已在输入中，模型主要做保真回显而非补充。**部分支持孙浩原「完整 PRD 信息有用性存疑」——仅就「验收信息密度」这一维度而言**。
3. **完整形态的不可替代价值在约束维度**：范围外 3 条 vs 0 条、约束/假设显式化——这是「知情决策、可治理」的关键，无法用验收字数衡量。完整形态的价值不在"写更多"，而在"边界更清楚"。
4. **锚点保真三形态全 true**：生产管线「PRD 只做语义补全、不改写功能项」约束在三种输入下均成立（F 维保真达标）。
5. **耗时**：简单形态最慢（补 4 项验收），一句话最快——若做极致成本控制，一句话形态省时但产出不可验收。

## 5. 对落地的建议（待团队拍板）

- **不建议**让用户只给一句话就进入 PRD——信息密度不足，产出的 PRD 无法约束后续工程。
- **简单形态（要点几条）是性价比甜点**：中等输入获得最大验收信息产出。
- **完整形态的价值定位应是"边界约束"而非"信息量"**：当用户有明确的范围外/约束时走完整形态，否则简单形态即可。
- 本实验为单需求（学习笔记）单模型（deepseek-v4-pro）结论，**跨需求/跨模型是否成立待扩样验证**——脚本已参数化，可换 `BLOMA_EXPERIMENT_*` 与 FORMS 定义复跑。
