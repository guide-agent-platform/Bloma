# Harness 执行基础设施改进（2026-10-28）

本批从 `sprint2 / 46e63cc` 开始，依据 [本次学习助手评估](../../outputs/bloma-session-assessment-20261028.md) 修复通用执行问题。方向是减少模型处理环境故障和重复失败的成本，不增加 PRD/多模型前置阶段，不限制产物布局或强制采用新的应用架构。

## 已实现

- **安装状态与失败证据。** `inspect_software_environment` 每次读取当前工程依赖元数据，运行时版本探针仍复用已有缓存；普通 npm install/i/ci 和直接 Electron 安装脚本执行后也返回安装状态。区分包缺失、元数据损坏和 Electron 包存在但二进制缺失，避免把局部失败解释为全部依赖未装。元数据/文件存在明确标记 unverified，不能签发运行或交付 PASS。
- **保留超时前日志。** 底层 DriverExecutionError 携带有界 stdout/stderr 尾部，命令工具脱敏后返回。安装错误区分下载连接、权限、完整性、安装脚本失败或超时，并附命令/当前清单与锁文件的散列身份，支持识别相同失败。未执行自动重装，也不清理已有安装或重置账本。
- **复用 Electron 下载缓存。** 使用 Electron 官方安装脚本实际读取的 `electron_config_cache`，指向 Bloma 私有共享归档目录。继续由原安装器验证缓存归档；各工程 node_modules、npm 缓存和业务数据保持隔离。没有硬编码镜像、替换用户模型或下载其它运行时版本。
- **统一简单 Electron 别名。** 命令执行与 GUI 观察共用 `electron-entry.ts`。`npx electron …` / `npx --no-install electron …` 直接解析到项目已安装的 Electron，不启动 npx 或联网下载。复杂 npm 脚本和带版本的包装命令仍需显式入口；缺失二进制时说明具体缺口。既有裸 electron 的命令执行回退兼容保留，GUI 不使用宿主运行时代替缺失的项目依赖。
- **窗口等待结合进程生命周期。** Electron 调试端口、CDP 连接和应用窗口分阶段检查；等待窗口时监测本次实际拥有的进程。进程提前退出立即返回身份、状态、退出码、脱敏日志及根因；EADDRINUSE 与 MODULE_NOT_FOUND 单独说明。CDP/HTTP200 不再被当作窗口就绪；取消仍保留原取消原因，清理只处理本次拥有实例。
- **重复失败不会被无关成功清零。** Pi 与兼容执行器保留不可逆推出原始文本的错误/命令散列。相同错误第 3 次提示，第 8 次仍未解除则以 no_progress 停止，保留现场和用量；普通只读空转仍为原 24 轮。打印文件或写探针不清除验收错误，另一条命令成功也不清除安装失败；相关工具/命令成功后清除该作用域记录。同批实际恢复不会误停，不同业务断言或清单/锁文件改变会区分。记录仅限当前执行，不重置既有请求、输出或金额保护。
