# V 未验证恢复与正常启动证据修复（2026-10-21）

本批修复 r5a 暴露的平台闭环问题。未修改 r5a 原样本、评分、V报告或封存运行树，未启动付费实验。直接原因及受控复现见 [诊断报告](r5a-delivery-diagnosis-20261021.md)。

## 修复后的行为

- V 的 findings 增加可选类型：product（有证据的功能错误）、evidence（缺证）、environment（审阅/环境问题）、advisory（不影响已确认功能的建议）。旧记录仍可解析。pass仍要求全部功能和实际证据读回；仅允许保留明确的非阻断建议，不把未知自动变成通过。
- 缺证交原负责人补执行证据，再走核心、安全、启动及V复核；明确功能错误交原实现者修复。无具体发现、执行异常或格式异常先有界重试只读审阅，不盲目要求改业务源码。
- 修复、补证和重试共用原 `quick-review` 持久化额度，最多2次恢复；切换分支或重入不能清零。V通过才清活动计数，历史total仍保留。取消后不查询，计数不可保存时拒绝恢复。
- 停止原因分别记录证据不足、审阅不可用、修复次数耗尽及恢复账本不可用，不再把第一次unverified写成“门禁耗尽”。停止时项目落 `verification-incomplete` 暂停状态，未交付。

## 正常启动路径

新增宿主 `normal_startup_probe.py` 和 TypeScript执行器，在v2 quick进入V之前生成 `00_VERIFY/normal-startup.json`。探针读取注册的Python入口，用独立APP_DATA_DIR启动真实pywebview，无dport、无HTTP业务调用；通过只读DOM观察原生API是否就绪、页面状态与首屏错误条，连续两次正常观察才通过。超时、无有效观察、报告保存失败、入口越界及验证期间源码变化都不能给通过；进程超时/取消沿用现有DriverSpawn的所属进程树收尾。

正常启动报告有源码指纹。适用项目的宿主检查失败或未完成，以及V没有读取这份报告，都会拦住V的绿色声明。该证据只证明正常桥及首屏状态，不替代六项独立业务验收，也不证明全部交互、所有原生窗口或所有UI技术栈已验证；当前探针面向骨架v2的Python/pywebview入口。

骨架 `ui/bridge.js` 从“仅重试120ms”改为监听实际pywebviewready并有界等待10秒，完成或超时均清理监听器。捕获的r5a UI在桥晚2秒注入时，使用新桥可以加载已保存任务，超过等待上限仍如实报错。驱动HTTP路径保持原协议。
