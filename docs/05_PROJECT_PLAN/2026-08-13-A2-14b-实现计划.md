## 2. 设计

### 2.1 新增：`main/mvp-engine-llm.ts`

新增独立的 LLM 生成模块（不动 `mvp-engine.ts` 现有模板逻辑，模板保留作兜底）：

```ts
export interface GenerateMvpLlmInput {
  project_id: string
  requirements: SketchRequirement[]
  query: SDKQuery                    // 复用 orchestrator 的 SDK 查询
  env: Record<string, string>        // 渠道环境（含 ANTHROPIC_AUTH_TOKEN 等）
  signal?: AbortSignal
  sessionId: string
  maxTokens?: number
}

export interface GenerateMvpLlmResult {
  files: GeneratedMvpFile[]          // 复用 mvp-engine 的 GeneratedMvpFile 类型
  run_command: string
  assumptions: string[]
  risks: string[]
  generated_by: 'llm' | 'template'   // 兜底标记
}
```

- **prompt 设计**（对齐 `api-spec §12.3 generate_mvp`）：system turn 要求模型只输出一个 JSON：`{ files: [{path, content}], run_command, assumptions, risks }`，含「纯前端、无外部依赖、可本地 `npm start`、connect-src 为 none（不得请求外部接口）」约束。
- **超时策略（对齐 interaction-spec §6 R-WAIT-03 的 120s 红线）**：LLM 生成设 **120 秒硬超时**。超时/解析失败/非 JSON/空输出/渠道不可用 → 统一返回 `generated_by: 'template'`（files 为空数组），由调用方走模板兜底。不做「继续等待」选项：LLM 输出是原子 JSON 无可分步展示的部分，超时即降级最诚实，且符合 F-01「快消型优先速度」。
- **文件安全**：`path` 必须白名单校验（只允许 `index.html`、`src/*.js`、`src/*.css`、`package.json`、`static-server.js`），拒绝路径穿越（`../`、绝对路径）；`content` 原样落盘（沙箱 CSP 已隔离脚本注入风险，但 `package.json` 必须只含 `start: node static-server`，不允许执行任意命令）。

### 2.2 接入 `runMvpTask`

`main/programming-orchestrator.ts` 的 `runMvpTask` 改造：

1. **解析渠道**：与 `runAgent` 相同逻辑——`getChannelByIdRaw(input.channel_id)` 或 `getFirstEnabledChannel()`；`decryptApiKey` 成功后 `buildSdkEnv`，失败则跳过 LLM 路径（直接模板）。
2. **尝试 LLM 生成**：`generateMvpLlm(...)`。
3. **兜底**：`generated_by === 'template'` 或异常时，回退现有 `generateMvp(...)`。
4. **后续链路不变**：`allowAutomatedTool('generate_mvp')` → `ensureSandboxRunning` → `createSnapshot` → analytics → `testing` → `mvp_ready`。LLM 生成的 `run_command` 必须仍为 `npm start`，sandbox/测试链不需改动。

### 2.3 类型与渠道复用

- `runMvpTask` 的 `MvpTaskInput` 增加可选 `channel_id?: string`（渲染端确认草图时带上，未传则 `getFirstEnabledChannel`）。
- `buildSdkEnv`、`getChannelByIdRaw`、`decryptApiKey` 均为已导出函数，直接复用，不重复实现。

## 3. 验收标准

1. **真实产物**：用户「基础四则运算计算器」确认后，`generated-projects/.../` 下是**真的计算器**（含 +−×÷ 按钮、运算逻辑），而非增删条目模板。
2. **兜底生效**：mock SDK 返回非 JSON / 抛错 / 渠道密钥不可解密时，回退模板，管线不中断，`test:all` 全绿。
3. **安全**：模型返回的 `path` 含 `../` / 绝对路径时被拒绝；`package.json` 的 `start` 脚本固定为 `node static-server`。
4. **测试**：新增 A2-14b 单元测试（成功路径 / 解析失败 / 兜底 / 路径穿越拒绝 / `run_command` 固定）+ 一个端到端 GWT 场景补「生成结果为真实计算器」。
5. `tsc --noEmit` + `npm run test:all` 全绿。

## 4. 测试计划（新增用例清单）

`tests/unit/mvp-engine-llm.test.ts`：
- LLM 返回合法 JSON（计算器：index.html + src/app.js 含 `calculate`）→ 文件落盘、`generated_by: 'llm'`、`run_command === 'npm start'`。
- LLM 返回非 JSON / 空 files → 返回 `generated_by: 'template'` 且 files 为空数组。
- LLM 抛错 → 抛错传播到调用方（由 runMvpTask 捕获走兜底）。
- LLM 超时（mock 流 > 120s 不产出完整 JSON）→ 返回 `generated_by: 'template'` 走兜底。
- `path: '../evil.js'` / `path: '/abs/path.js'` → 被过滤。
- `package.json` content 被强制重写为固定 `start` 脚本（忽略模型给的任意命令）。

`tests/unit/mvp-engine.test.ts` 增补：
- 兜底测试：`generateMvpLlm` 返回 template 时 `runMvpTask` 产物与现有模板一致（保持既有断言）。

`tests/unit/programming-orchestrator.test.ts` 增补：

## 5. 风险与决策

| 风险 | 应对 |
|---|---|
| 模型生成代码可能不可运行 | 保留 `runPostMvpTestingFlow` 自动测试 + 修复循环（已有），测试失败进 repair，3 次失败回滚快照 |
| LLM 生成耗时长 | **120s 硬超时**（对齐 R-WAIT-03），超时即模板兜底，管线不中断；等待期间 `generating_mvp` 已广播，渲染端按 R-WAIT-01/02 显示 5s/10s 反馈（既有机制，不新造） |
| 模型输出体积超 token | 限制 `maxTokens`（生成侧可调大，如 4000），files 数量设上限（如 ≤10 个），超限截断或兜底 |
| 渠道不可用 | 全程 try/catch + 兜底模板，绝不中断确认→MVP→测试主链路 |
