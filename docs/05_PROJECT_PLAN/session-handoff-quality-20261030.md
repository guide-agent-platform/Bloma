## 5. 当前质量协作方案

职责按信息面区分，不要求五个常驻Agent：

- A：唯一制作与集成负责人，负责实际运行和修复。
- B：实现前从确认需求/设计给出独立业务案例；不看实现，不新增需求，预期不明就保留争议。
- C：对稳定候选只读审代码/数据，提交触发条件、需求依据、证据和复现建议，不继承A的成功叙述。
- V：看同一候选真实图片与必要DOM/操作事实，找布局、静态残留、状态及对象错配问题；有附件不等于看过图。
- R/W：限定侦察或文件范围明确的实施工人，按需要使用，不每次全开。

主链：冻结目标 → B案例 → A可运行候选 → 冻结候选 → C/V独立找错 → 宿主复现 → A修复 → 新候选复测 → 交付。模型只给finding，不能靠投票或“已修复”关闭缺陷；宿主真实证据绑定当前版本。

问题契约及状态详见质量方案第4节。重点是疑点与已证实缺陷分开、预期来源可查、重要已确认问题必须闭合、范围外建议不阻塞，修复变更使旧审阅/图片失效，保留失败及未验证项。
