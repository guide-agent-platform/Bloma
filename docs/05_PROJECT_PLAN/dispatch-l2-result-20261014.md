## 准备阶段发现并处置的问题

1. 驾驶脚本漏掉澄清卡族，并且按钮标题后带说明文字导致匹配不到。修复两种卡片识别和同会话续接；准备重开后原卡片不会自动恢复时，使用明确自然语言回答，没有重建原需求。
2. 原驾驶自动确认将“向导补充”也采纳，其中冲突时提供覆盖选择违背原边界。新增确认前取消向导补充；本次已通过自然语言撤回该建议，最终 PRD 标为范围外。原始记录保留。
3. 结构化 PRD 两次达到 8192 输出上限而无法解析。准备渠道改为 16384 后，模型补了一次规则覆盖，结构检查通过；最终 PRD 17 功能、18 规则、51 场景，open_questions 为空。备份 JSON/稳定 ID/冲突整份拒绝的澄清答案先于实现封存。
4. 准备渠道的 16384 不是所有辅助角色的统一硬限：内审委派仍使用其原有独立输出设置，账本可见 7.217152 元的逐请求最坏预留（输出预算 640000）；均获得用量后核销。执行恢复重新 seed 为 8192，47 次 executor 请求均记录 low 思考档。后续准备阶段需继续审查角色预算，不能把渠道配置等同于全链输出上限。

驾驶脚本 6 项针对性回归、Node 语法检查、docs:check 通过；平台 TypeScript 和构建未改，不重复计入此前全量测试结果。
