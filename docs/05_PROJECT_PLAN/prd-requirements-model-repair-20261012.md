# PRD 需求模型改造（2026-10-12）

依据：本会话用户确认实施；[当前失败链路](prd-production-path-audit-20261012.md)、[Proma-Easy 对照](prd-proma-easy-comparison-20261012.md)。参考分支固定 df23df7d121d349e6a58365f3207e9b0047c59c5，吸收同源、验收前置、版本绑定原则，没有整体移植调度器或平台范围。

## 已实现

1. 新增 requirements_model v1：目标/目标用户、宿主保存的原始来源、业务对象与关系、完整使用流程、跨功能业务规则、正常/边界/异常验收场景、逐来源处理说明、待确定问题。功能仍放在既有 requirements，通过编号关联，不维护另一份能力清单。简单工具可没有独立对象/规则；功能数量不设 3–5 项硬上限。
2. 主 PRD 产出改为同一次模型调用组织功能与业务模型，不再在未经拆解的冻结清单上并行跑正文和旧加厚腿。模型候选清单不是冻结范围，自动选择也必须走组织步骤；原话和让渡占位不再前置为 F-001，也不因数组位置重排功能编号。
3. 新模型的正文由宿主投影生成，兼容 acceptance 和行为断言从场景派生；模型另写的 document/acceptance 不成为独立权威。用户看到业务语言的目标、对象、流程、规则、场景和来源，运行形态与反馈用可读表述；完整结构仍供工程与审查消费。
4. 原始来源读取完整多行 user 消息，排除助手自述和纯控制选择。需求勾选/明确不采纳、采纳新想法保存实际选择含义。确认卡采纳新增能力须重新组织模型，再过审查/确认，不能把只有描述的新项直接塞进已确认范围。
5. 确认前检查引用、编号、来源处理、流程覆盖和三类场景；共享规则须在每个关联功能的非豁免场景覆盖。结构性问题与待确定问题不能通过忽略/确认绕过。提炼失败/保存失败暂停，不继续假装已形成完整 PRD；返回真实检查原因并有限重试。
6. 攻击、Defender、复核均收到完整背板，包含正文、验收、假设和业务模型。Defender 合法 assumptions 更新保留；新模型可补齐多项能力并同步关联，但不能改写宿主来源、换编号含义或伪造用户约束。工具即时校验并报告采纳/拒绝字段，非法提交允许修好再交。
7. “全部交给向导决定”现在实际执行有预算的修订/复核，通过后保存并转确认；未收敛保留问题，不再记录为忽略。一次额外委托未收敛后撤下全局委托选项，要求具体处理，不自动无限重复同一轮。
8. 业务模型和假设进入验收证据哈希；规则/场景/来源变化会使旧证据失效。新模型确认后不再额外改写一套 EARS 断言；旧项目仍保留兼容路径。

旧项目没有 requirements_model 时仍可读取；本批没有迁移历史项目、修改真实提示词覆盖文件、修改旧生成产品或推送远端。覆盖提示词仍提供风格/业务补充，主产出协议由平台追加并优先执行，不会因旧覆盖而继续冻结主题。显式兼容调用可保留旧格式；实际主产出默认使用新模型。

## 真实输出暴露后的补修

规则适用功能与场景的规则引用原本要求模型双向填写，容易形成重复声明不一致。现在由宿主合并“规则显式关联 + 场景已声明引用”得到规则适用功能，保存生成关联说明。只使用模型已有的正式引用，不新增场景、规则、断言或功能；未知编号和缺少适用测试仍拒绝。直接校验器继续要求规范模型一致，归一发生在模型解析阶段，正式模型和文档仍同源。

同时把真实模型每次输出、校验原因、关联归一说明和输出哈希保存到所属项目 diagnostics/prd-organization-attempts.jsonl，最多保留每次正文前 65536 字符并注明是否截断；不会进入正式 PRD、不会打印渠道密钥。修复 PRD-only 驾驶器识别本轮结构失败的终态，避免为已失败的 PRD 空等交付。

补修类型检查、构建及 **6 文件 / 68 例**针对性测试通过（prd-model-links-*）。包含已有场景反向关联、未发明测试、未知规则继续拒绝、原输入不被修改，以及失败输出独立留档。补修后再次全量单测 **255 文件 / 2305 例通过**，日志 prd-model-full-unit-links-verified.log。工程先后固化为 ee72521、db9b78b。
