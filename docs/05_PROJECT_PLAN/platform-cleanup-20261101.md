## 范围与判据

从main启动、IPC/preload、renderer入口，经过composer持久接收、流程/渠道分发、制作/委派、Pi、工具、验证与发布逐段检查。用esbuild入口依赖图核对410个TS/TSX模块，再检查未进入bundle的文件是否还有脚本入口、类型引用或历史资料读取用途；“没进bundle”不单独作为删除依据。

本地上游参照 `proma-upstream` 的 `bf3e98c`、`apps/electron/src/main/lib/adapters/pi-agent-adapter.ts`；实际能力以已安装的Pi 1.4.0为准。保留Bloma自己的项目权限、物理请求/金额守卫、工具回执和交付裁决，不把它们误当成可删除的SDK重复层。

## 第一批：仅保留Pi执行器

原来software-v1显式选择Pi，但省略`runtime`仍进入自写执行器；委派及不少测试因此存在两个执行语义。现删除旧循环、自写交接压缩/宽限总结/并行批次调度、文本DSML恢复执行器和运行器选择字段。`runAgentLoop`只装配材料、管理宿主转向生命周期并进入Pi；主任务和委派使用同一实现。

同时删除手写的部分JSON Schema校验器，使用Pi原生完整schema校验。迁移有效合同测试时确认并修复：

- Pi默认会转换工具参数类型，例如把`path:42`转换为字符串。宿主通过原生`beforeToolCall`比较原始和校验后参数，拒绝隐式转换，不执行工具、不消耗工具次数预算；schema校验仍完全归Pi。
- 畸形图片短引用在Pi适配前过滤，避免空引用导致运行异常；图片字节仍仅在已有授权水合出口读取。
- 工具耗时直接采用Pi原生`durationMs`；没有允许字段时不制造空detail，原始取消原因保留为有限长度的宿主观测。

旧执行器专属的压缩阈值、宽限轮、手写并行器、文本伪工具恢复测试随实现退役。当前权限、schema、工具预算、取消、原始审计、消息配对与图片断言迁移到Pi；原生会话恢复、不重放副作用、压缩、供应商重试、转向和费用守卫由现有Pi/生产测试验证。原始审计保存完整工具结果，供应商投影排除孤立工具结果，事件摘要单独限长。

验证：8文件64项通过（`pi-only-final.log`）；2文件5项真实Electron/本机HTTP集成通过（`native-loop.log`），包括实际图片字节与原生会话恢复。类型检查和完整构建通过。全量单测随后执行，结果在本记录收口时补充。早期失败日志保留，未把测试脚本问题或旧实现格式断言当作当前产品失败。
