# 仅功能需求的真实 UX 冒烟：计数器

日期：2026-10-17。基线 `ef1f38a`，本次补充 PRD 豁免场景的 UX 校验修复。

原始需求只有一句：**做一个计数器，可以加一、减一、清零。**

没有在用户需求或临时覆盖中加入配色、布局、参考作品或审美要求。使用当前配置的 sketch 路由 DeepSeek Flash；默认产品设计提示词仍由平台自动附加。为减少无关调用，直接将功能整理为最小 PRD 输入现有 `generateUxSketch()`，未运行向导澄清、PRD 模型生成或后续软件实现。这是一次真实静态 UX 生成测试，不是完整软件交付。

## 结果

- 首轮试跑的两次响应都生成了完整 HTML，但设计关联未通过，最终如实返回机械模板；两份模型响应与模板全部保留。
- 原因是 PRD 已明确 `not_applicable` 的异常场景仍被 UX 校验要求覆盖。第一次模型把它放进非界面功能，与界面功能声明冲突；第二次去掉该项后又被判场景遗漏。
- 修复为：只有适用场景必须落实到界面状态或非界面职责；明确豁免的场景不要求虚构界面。宿主索引单列豁免原因，协议说明不能把一个界面功能的豁免场景转成非界面功能。功能覆盖、适用场景关联、错误编号和界面/非界面冲突校验保留。
- 原响应不改内容重验：第一次仍被拒绝，第二次通过。说明修复针对豁免语义，没有取消界面/非界面冲突检查。
- 再用相同功能输入进行真实复测，首轮通过，`source=llm`，输出 9019 字节 HTML，约 11.6 秒。视觉呈现为暖白底、橙色主按钮、醒目计数和三种静态状态示意。
- 1100×800、820×700 两个窗口渲染均无横向溢出，已查看实际截图。界面已脱离默认需求块列表，具有统一配色和排版；单例不能证明审美普遍提升，底部状态说明也仍有原型展示痕迹。
