## 最终修改

- 确认卡与随后的静态阶段事件属于同一轮，不再因为短流程没有文本输出就清掉卡片；新增实际事件顺序回归，保留旧澄清/让渡流程。
- 需求以结构化目标、功能、可观察结果、约束和本次不做的事项展示到主面板；三个操作集中在底部，去掉用户界面上的F编号与180px聊天摘要限制，聊天栏不再重复放一套确认按钮。
- 历史加载只读返回pending_decision及可用预览地址，不发模型请求、不消耗确认、不自动开工。核对项目、会话、需求范围和实际草图字节；损坏或过期内容不给确认按钮。迟到历史快照不覆盖新的实时决策。
- 界面设计实际发generating_sketch阶段，显示明确等待说明，侧栏不再回到“想法”；首次需求整理也发出可见的开始信号。
- 完整草图仍为默认展示；适应窗口、原尺寸和缩放由用户选择。人物提醒移入聊天栏并缩为小图，不覆盖产品内容；修正其与聊天输入区的伸缩布局。
- 正常预览与已确认草图回看默认不加载宿主点击拦截，主动点击“标记修改”才进入标注，退出后恢复普通交互。旧脚本捕获所有click并preventDefault，导致普通草图点击也被吞掉；此处已修复。只对返回的预览响应移除宿主标记，不改冻结HTML、不重算或伪造确认摘要，保留产品原有HTML和脚本。
- 界面旁白使用“需求、软件制作”等用户用语，不再对浏览器任务硬写“桌面交付”。进入制作不额外插入机械的伪用户气泡，UX/跳过草图两条路径的完成和失败说明均真实落盘。
- 短任务单提示区分制作过程偏好与成品功能；草图提示要求搜索、列表数量、保存状态自洽，支持无脚本的少量页面状态。仅修改提示，尚未在新付费生成中确认效果。
