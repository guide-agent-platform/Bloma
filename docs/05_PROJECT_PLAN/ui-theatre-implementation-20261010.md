# 软件剧场 UI 落地与输出适配

日期：2026-10-10（北京时间）。起点 `sprint2 / ae04dff`。用户认可第二版方向并要求应用，同时指出模型回复需要精简；随后反馈真实实现细节与尺寸不够好、需要使用展示稿图标、快速型对话宽度被压缩、滚动条过重。emoji 的专门渲染按用户要求后置。

## 当前实现

- 工作区改为中央软件窗口、下方持续对话、按需资料面板。保留原有发送、附件、语音、回执、恢复、停止、确认、启动、导出、纠错、历史与回滚接口和自动化锚点。
- 顶栏集中品牌、项目切换、模式和设置；渠道状态移到资料入口旁。快速型紫色，长期型绿色；系统浅/深外观使用同一组语义色。
- 普通对话默认展示当前轮，完整历史随时展开。长回复保留全文并提供展开入口；切换历史与资料不重建输入框。运行信息、错误和确认操作继续保留。
- 首页可以先写想法；项目创建后以持久草稿、同一 client_message_id 与真实 chat:submit 接收链发送。接收失败保留文字和待确认身份，在途新输入不被清理覆盖；没有把 initial_message 冒充已发送消息。
- 交付文件与说明按需展开；空项目不先显示缺失启动声明和“零文件”列表。正式启动仍由原 can_launch 与主进程校验控制，程序在独立窗口运行。保存的程序截图为静态预览。
- 使用 `lucide-react@1.55.0` 的官方图标，与展示稿同为 Lucide 线性风格、2px 笔画；保留原图标模块出口名。附件、历史、文档、材料、版本、协作、设置、复制、关闭、播放等入口不再使用手绘近似或字符按钮。聊天文本的 emoji 渲染机制未增加替换器。

## 尺寸与反馈修复

原主窗固定 1280×820、最小 1080×720；改为从当前屏幕 DIP 工作区计算初始与最小尺寸，保留边缘空间。默认英文菜单折叠，原生菜单仍可用。没有修改 Windows 系统 DPI。

中央窗口使用导航和对话之外的剩余空间，取消固定 40vh 与固定对话高度叠加。较窄窗口的资料在软件区域内展开；极矮的有效视口采用整页滚动，让输入和操作可达，避免用小字号硬塞。输入框按内容和可用宽度调整高度。

快速型的差异来自旧连接提示卡的 `width: fit-content`、居中与额外左右内缩。紧凑呈现统一为铺满可用消息宽度、左对齐，助手回复与系统提示沿同一基线。消息尾部定位元素在紧凑模式不再制造额外空隙。

外层容器明确采用 border-box，修复边框额外高度引起的无意义整页滚动。滚动条统一为 6px、透明轨道、无箭头、轻灰滑块，悬停加深；粗指针有更宽命中区域。没有禁用滚轮或键盘滚动。

## 模型输出

`main/agent/prompting/user-facing-output.ts` 为向导/编排器提供呈现约定：普通说明 1~2 句、尽量 100 汉字以内，保留结果、必要决策和下一步；完整需求、PRD、约束、验收和材料引用继续进入原结构化字段与文档。

向导在实际 loop 请求的系统提示末尾追加约定，包含本地 guide 覆盖版；桌面编排器经输出纪律装配。没有给实现者任务书、PRD 生成、工具 JSON 或验证证据施加用户说明的长度建议，也没有缩减编码预算。失败、阻塞、补充功能、未验证与用户明确要求详细解释属于例外，不能为了短而隐瞒。

这是生成约定加界面兜底，不是硬截断。用户主动查看时仍能取得原回复；原会话落盘不被重写。本轮用真实请求装配边界替身测试确认接线，没有新发真实供应商生成单，不能据此宣称所有模型已经稳定遵守字数建议。
