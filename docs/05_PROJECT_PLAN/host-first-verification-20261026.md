# 无法准入模型时先执行已有验收 · 2026-10-26

保留既有金额政策、费率、账本和未知责任。当显式金额政策的整输入预留已经超过可用余额时，新的输出长度也无法让请求合法准入；不必先调用模型再收到拒绝。

软件生产入口现在可以直接执行已经冻结的 GUI/CLI 检查，仍必须通过真实业务、安全、启动及版本一致性检查才能交付。临时在途预留不被误当成永久耗尽；等待释放的请求继续沿原准入逻辑处理。损坏政策或账本不会被当作免费放行条件。

只允许继续既有目标或本轮已有有效验证凭据时这样收口。新增/修改请求尚未由模型处理时，不能用旧版测试冒充新请求完成。模型运行后也不会在没有任何源码变化和本轮验证证据的情况下，把未处理的新请求当作完成。

验证：harness-native-complete-regression-20261026.log 的 7 文件 54 项通过，其中金额 21 项、宿主收口 11 项；检查包含有规则/无规则、新需求保护、失败、取消、账本不可读及真实命令执行。集合与先前目标回归重叠，不额外叠加计数。没有增加供应商请求或改变任何原账本。

本批没有实现精确输入 token 计数，也没有解除金额硬上限。标准原生应用测试的正式验收接入另见 native-acceptance-delivery-20261026.md。
