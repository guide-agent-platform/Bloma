用户指出通透画室与更早版本仍相似，除非对话栏做出实质改变。因此下一轮将评审对象收窄为对话组织，暂不把新的背景、阴影、人物大小当作方案已发生突破的依据。

- **人物对谈**：当前人物发言、用户回复和本轮确认组成一个对话回合，人物紧邻发言区域。回复框承接当前发言；发送后保留最近用户回复，完整历史随时展开。长文本、自由输入及未发送草稿保留，不把用户限制为预设按钮。

两种方案都固定浅色、复用现有角色形象。发送和回复均为固定本地交互示例，不接模型，不更新真实需求、确认记录或产物。意见状态区分已收到、待调整、已提交；示例不会把收到消息或出现回复当成草图已经修改。自由回复的固定文本不构成模型语义理解能力证明，落地时必须区分普通交流与明确的修改意图。

- 保留已有语义形象池；“换个形象”仅为评审按钮。正式选择仍绑定同一确认环节，不改变业务状态。

## 首版对照方案

本轮交付两种可交互布局、六种固定场景及人物形象变化规则。平台 renderer、IPC、执行逻辑、确认记录与现有正式素材没有在本轮替换。本轮不触发平台的软件生成、执行或付费狗粮。

## 设计目标

仅做浅色主题，不提供黑色/深色主题，也不随系统切换。保持星屿画室的淡紫、鼠尾草绿和东方 Project 同人插画气质，让用户看着同一个作品从需求走到试用。柔和气质由配色、角色和自然交流表达；内容通过深色正文、明确状态和清楚的主操作建立层级。

用户本轮补充：必要时可依据主页立绘重新设计动作，保持东方 Project 二次元风格；现有示意图应先复用；重复出现时可以随机选择形象。预案将后两项落实为已有素材优先、按语义选择形象、当前环节保持稳定。

评审目标：选择日常工作区的空间组织，并检查需求确认、界面确认、制作、验证中断、主动停止、试用六个场景是否连贯。

## 两种布局

### 作品画室：建议优先评审

左侧窄项目栏，中央完整作品，底部常驻输入。对话历史由“对话”展开；输入和发送始终存在。当前作品、制作进展、恢复与确认操作集中在中央，人物在作品旁的独立区域出现。

- 产品草图可获得较大连续空间，适合看布局、找问题与试用。
- 需求确认时中央改为结构化范围，聊天负责补充。
- 底部是短输入与最近回应，不重新建立一个低矮且持续滚动的第二工作面；需要历史时主动展开。
- 长对话、附件、长文本编辑仍需完整对话视图，落地时应保留稳定的展开入口和草稿。
- 人物收起后作品自然获得空间，不留空槽，不改变当前选择和草图实例。

### 并肩工作台：保留对话连续性

左侧窄项目栏，作品为主、对话为辅的双栏；执行状态附着在作品下方。对话承担历史与补充，避免同时承担第二套进度和主操作。

- 适合高频补充、对照讨论与反复调整需求。
- 对话初始宽度约 300–340px，允许拖动并保存偏好；宽度不足时切换视图，不能把作品持续压缩。
- 人物图占用独立边缘，避免挡住草图或输入框。
- 与作品画室共享执行状态、成果身份、主操作和人物规则，便于比较布局自身的影响。

原型在窄于桌面宽度的会话显示环境中进行上下重排；该重排用于保证预案可读，不把浏览器宽度等同于实际 Electron 窗口适配已经完成。

2. 最近进展：来自真实事件的最近结果；只展示少量用户能理解的摘要。
3. 下一步：系统会继续什么、是否需要用户决定。
4. 当前操作：停止、继续修复、确认或打开试用。

不展示按阶段数折算的总体完成百分比。经过 10 秒、120 秒等阈值可以展开更多信息，但不能用时长推断仍在正常执行。无新活动应写明最后一次有效结果，而不是自动轮播安抚台词。

执行状态的准备、运行、等待确认、重试、失败、用户停止、完成验证与交付分开表达。文案依据后端可证实的状态，不通过聊天文本猜测。执行详情、技术错误和完整调用记录放进“工作记录”，主画面说明实际影响和可行动项。

恢复操作必须与能力相符。原型使用“继续修复并重新验证”，不声称精确从某个失败工具步骤重放。恢复时保留已确认范围、草图、已有文件；可用版本和文件保存状态由后端检查，不能套用无条件“全部保存”或“绝不会影响电脑文件”。

### 先复用的素材

- 需求确认：`guide-prd-v2.webp`、`guide-clarify-v2.webp`。
- 界面确认：`guide-sketch-v2.webp`，或主页平静站姿作为等待回应的变化。

只在某个交互角色缺乏合适素材时增加新动作。新增素材应先生成完整姿态、确认脸型/服装一致性，再考虑轻量动态。不要为追随指针而让手臂穿插、关节变形或遮住按钮；不循环播放敲代码、点头等虚假忙碌动作。

本轮先行发出的三姿态概念图仅供后续参考，没有接入原型，也没有替换正式素材。人物随机化不依赖这张图。

### 形象随机规则

按语义分池，而不是所有图片混抽：

| 语义池 | 合适姿态 | 约束 |
| --- | --- | --- |
| 核对需求 | 捧文稿、倾听、思考 | 不使用庆祝或催促 |
| 展示界面 | 展示、轻指引、平静等回应 | 手势朝向作品，人物不覆盖作品 |
| 邀请试用 | 轻微笑意、开放手掌邀请 | 必须已具备真实试用条件 |
| 异常与恢复 | 平静、认真，或不显示 | 不随机出现兴奋、脸红佯怒等趣味表情 |

正式选择键建议由项目、会话、确认范围版本、事件类型组成。新一轮确认事件到达时，从适用池选择并尽量避开上次同池形象；同一事件的重渲染、窗口缩放、滚动、打字、回看、重连与历史恢复保持选择。不因为重新随机触发新文案或重复播报。

同池仅有一张合格图时正常复用；图像加载失败时退回完整静态姿态或隐藏，确认与发送始终可用。必要的身份/位置/表情兼容条件优先于追求随机。演示中的“换个适合的形象”仅为评审控件，正式产品无需出现。

安静模式是独立偏好，隐藏阶段立绘并减少动态；保留文本、进度和主操作。系统减少动态效果偏好优先。人物显示记录与业务确认分开，收起或看过角色绝不能消耗确认记录。

## 视觉细化

- 页面只保留必要层次：项目导航、作品表面、按需资料/对话；降低层层卡片、阴影与浅边框的重复。
- 重要标题和正文使用深色，紫绿用于关键操作与状态点缀；普通正文建议 14–16px，操作与主要辅助状态 13–14px，时间戳等真正次级信息才用较小字号。
- 圆角按语义收敛为控件、作品表面、浮层几个等级；人物区域不另套大卡片。
- 角色、标题与操作保留固定区域。阶段改变时不抢输入焦点、不重载草图、不清除补充草稿。
- 需求确认或作品内容较长时，主操作与输入可达；实际 Electron 需验证 Windows 缩放、键盘及窄窗口，而非只检查 CSS 断点。
- 首次具备真实试用条件时，状态文字、试用入口与人物邀请同步变化；可用克制短过渡，减少动态模式下直接呈现。独立桌面窗口由真实启动路径打开。
