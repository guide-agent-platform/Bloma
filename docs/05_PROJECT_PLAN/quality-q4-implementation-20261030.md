# Q4：按实际差异选择协作

日期：2026-10-30（Asia/Shanghai），起点 `69ff1ed`。本批实现 Q4 的宿主协作选择；复用现有 Pi、委派、发布候选、台账和验证。没有新增经理 Agent、异模型路由、子会话执行权限或另一套运行引擎，也没有调用真实供应商。

## 选择规则

`collaboration-selection.ts` 读取现有真实文件清单、已验证发布基线、基线独立审阅记录、当前确认目标/环境及重要 finding。模型没有 risk/skip 参数；`inspect_collaboration_plan` 只接受空对象，返回宿主决定、差异与理由，不签发 PASS。

| 当前事实 | 自动选择 |
| --- | --- |
| 新项目、没有完整发布基线，或基线/来源/目标/环境不完整 | C；有界面时还须 V |
| 逻辑、数据、依赖、配置、测试、文件增删、文档或其他未知变化 | C；有界面时还须 V |
| 已验证 GUI 基线上，最多两份已有 CSS，旧/新文件各不超过 32768 字节，AST 结构与非样式值保持，仅允许现有颜色、边距等限定值变化 | 只选 V，必须看当前候选真实图片 |
| 源码/依赖清单、确认目标、环境与已验证基线相同 | 不重复自动 C/V，仍执行原宿主检查 |
| 重要已复现缺陷尚未在当前候选闭合 | 保留完整审阅与原复现/复测义务，小改动不能消除缺陷 |

CSS 用仓库原已安装的 PostCSS 8.5.26 解析，现将其固定为直接运行依赖。比较选择器、规则/at-rule 参数、声明序列、属性和 important；只允许限定属性的有界样式值变化。显隐、定位、交互、静态 content、新增声明、URL/变量等不确定的值变化、解析失败或超限均保留完整审阅。未变化的其他 CSS 值不会被任意擦除再比较。该分类仍是保守的风险启发式，不是 CSS 或程序行为的完整语义证明；并不保证所有小改动都能省去审阅。

不把模型说“小改动”、模型自报 PASS、只有 C 摘要或测试退出码作为缩减依据。即使只是 README 改动，发布清单发生变化也按未知处理；没有增加宽泛的文档/后缀免审白名单。

## 版本与证据

每次决定保存到同一 `software-quality` 台账的 collaboration 历史，绑定 policy version、当前源码/目标/环境、已验证基线 ID、选择的角色、原因和实际差异（最多显示 64 条，同时保留总数）。相同事实去重，不让模型写入“低风险证书”。输入在选择期间变化拒绝缩减，不能使用旧决定。

最终发布凭据增加 `collaboration_id`，在现有主线最后检查后绑定本次宿主决定。下一次基线若是合法的“V-only”发布，可通过这个绑定核对上次未选择 C 的原因；不会因为没有新增 C 记录而错误地下一轮又强开 C。缺少、损坏、不匹配或未知版本的选择凭据不能替代必需审阅。

未选择某角色与“本次该角色通过”分开记录：不伪造 completed C/V，不把过期旧图片当当前图片。V-only 仍使用 Q2 的当前截图、子会话授权、真实图像传输与观察门；未变化候选基于已验证发布事实选择不重复审阅，旧图不是新视觉 PASS。

B 的用途、独立预算和语义争议门不变；重要 finding 的源码/规则绑定、关闭证据门不变。核心、GUI/CLI、独立案例、能力、安全、正常启动、发布完整性与最终版本检查均未被协作选择跳过。也不绕过同一路由明确拒绝图片时的停止规则。

## 工人与费用边界

当前没有证据要求再加写入工人或开放测试子 Agent。继续复用独占 write_paths、主负责人集成/运行、活跃写入冲突检查、停止与回收；软件委派最多两个并行，继承父模型及共享请求/输出/金额预算，普通子任务仍禁止渠道覆盖。R/W 按已有明确子任务按需使用，不因“高风险”自动额外启动模型。需要独立命令/GUI 执行隔离或异模型用途时，仍须具体设计、验证和对应授权，本批未宣称已提供这些能力。

## 验证

- `collaboration-selection.test.ts` 最终 15 项用受控宿主基线元数据检验选择器，不当作真实 GUI 交付验收：无基线、纯样式仍需 V、模型参数不能越权、JS/配置/README/新增 CSS/结构/静态残留/URL/过大 CSS/语法错误保留完整审阅、旧决定失效、基线字节损坏及重要问题不被小改动消除。即使凭据校验和一致，full GUI 选择缺少 V 也不能缩减协作。
- 扩展原真实 GUI 制作测试：先经过 C/V、真实缺陷复现与修复、宿主验证并发布，建立真实基线；随后仅修改颜色/间距，先复测既有重要缺陷，再只新增一个 V，完成正常验证与发布；随后未改变实现的明确核对任务只调用一次受控 A，不新增 C/V 或本机视觉协议请求，仍完成宿主验收。发布凭据与宿主选择 ID 一致，实际请求仍计入原共享预算。
- 两并发、文件冲突、取消、共享费用、B 争议、真实图片与旧证据、恢复/预算停止、原交付链继续回归。所有模型回复为受控 query 或 127.0.0.1 的 HTTP/SSE fixture，没有真实供应商请求。

首批 3 文件 26 项通过；真实入口接线后 6 文件 32 项通过；相关回归 16 文件 108 项通过，轮次重叠不累加。随后发现 PostCSS 的 CommonJS 被 ESM 主包内联产生动态 require，改为原生 createRequire 加载固定运行依赖；修正后补强缺少必需 V 的凭据反例，最终选择器/委派/架构 4 文件 24 项复验通过，类型和构建通过，主包 `__require(` 调用数为 0。最终构建运行原隔离 Electron 启动脚本 `S0-UI-007` 实际通过，测试实例使用独立 PROMA_HOME/user-data 并退出，未重启用户现用实例。没有因此声称干净机器、安装包或完整用户实例验收。

PostCSS 及其原有传递包版本/完整性保持原锁定值，离线更新了运行依赖标记，未运行安装生命周期脚本。证据在 `run-artifacts/q4-initial-tests.log`、`q4-integration-tests.log`、`q4-final-tests.log`、`q4-loader-final.log`、`q4-typecheck.log`、`q4-build.log`、`q4-native-smoke.log`、`q4-dependency-lock.log`。真实基线→V-only→unchanged 的台账在 `run-artifacts/q4-selection/production-ledger.json`，属于本机忽略证据，不随提交传播。

本机结果证明按当前规则减少了受控重复审阅，并保留必要证据门；不证明真实模型费用/耗时收益，更不证明真实软件生成质量已经提高。Q1–Q4 的本机机制已接线，仍需新的明确任务、渠道、费率和完整预算后才能开展真实模型质量验证；旧实验和余额不自动恢复。
