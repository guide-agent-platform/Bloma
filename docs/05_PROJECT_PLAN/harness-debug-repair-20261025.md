# 调试工具与费用拒绝反馈修复 · 2026-10-25

基于 150b9ba 的学期任务台轨迹，免费修复已证实的 harness 缺口。没有新增真实模型请求，没有改动原项目、冻结业务预期、费用授权上限或历史账本，也没有手动把未完成项目标为交付。

## 原因判断

Codex 的公开工程循环是编辑、运行工具、观察真实结果、修复和复验；工具反馈与可持续的外部项目状态很重要。参考 [OpenAI 官方说明](https://developers.openai.com/blog/run-long-horizon-tasks-with-codex)。本轮独立 Playwright 验收可以直接选择下拉项，而 Bloma 工具只暴露 fill/click 等有限动作，造成模型误用后改造产品控件。这是已定位的工具能力缺口。

提示词和 inspect_app 描述承诺“源码变化自动重载”，但显式 mode=act 分支没有执行这个承诺，两次 DEBUG_SOURCE_CHANGED 不能完全归责为模型忘记 reload。制作迟迟不登记最终验收则同时涉及执行策略与模型取舍；目前没有相同任务、工具、预算下的跨模型对照，不能分配归因百分比或据此判断模型能力上限。

## 本次修改

- GUI 动作新增 select，通过 value 或 label 精确选择原生下拉项，端到端接通公开 schema、解析、GUI 登记与 Electron/浏览器观察器。缺失或歧义选项明确失败；不修改产品控件来让测试成功。
- 兼容已有原生会话的 fill(select,value)：先按选项 value，必要时按唯一可见文字选择，真实触发原生 change/input 行为。普通文本输入保持原动作。
- 显式 mode=act 与默认调用统一处理源码过期：重启实际入口、增加观察版本、保留隔离开发数据；旧观察仍属于旧版本。只读 read 不重启、不把过期页面认作新代码；入口声明变化等保护保持有效。
- 工程指导改为主路径能运行时尽早登记业务检查并 verify_app，再修具体缺口。没有新增阶段、固定额外审查或强制更多模型调用。这只是指导改善，尚未用付费模型证明行为已经改善。
- 费用拒绝保留稳定机器错误码，同时携带金额上限、已计入责任上界、已报告计价、未结算请求预留、下一次请求所需预留、可用金额及差额。Pi 会话适配会把错误转为字符串，因此在本次查询边界保留原拒绝对象，再接回最终用户提示和持久状态。
- 普通金额拒绝提示不再笼统说“预算已用完”。已有验收规则时仍可停模型、继续免费宿主检查；缺规则、业务失败、取消均不能制造完成或 PASS。

## 费用保护的范围与保留事项

此前触发的是隔离付费测试所设置的追加 3 元窗口，不是供应商统一限额。本轮修复没有解除这份明确的支出上限，也没有启用无限金额实验开关。

原算法仍按整模型上下文和输出上限预留，这是此前提前停止的直接原因。本次只修复说明和传递，不宣称已经解决过大预留。将其改为真实请求的计费上界，需要可信计数或可证明的供应商上界；字符长度近似值、缓存命中猜测、删除未知责任都不能直接充当硬支出保证。后续应先实现可信的请求计数路径，再调整准入算法，并让预算状态提前可见。

核对原追加窗口仍为 53 次物理请求，全部已报告，计价上界 0.841395 元。学期任务台仍保持原来的未完成终态；本轮回归通过不等于该付费案例已重新完成正式交付。

## 后续优先级

先让调试动作与真实工具能力一致，缩小错误反馈损失，及早登记并运行可重复业务检查；然后完善可信金额准入。下一轮真实模型运行应在同任务、同范围下核对工具错误、改代码次数、验收登记时点、费用与总耗时，再决定是否需要模型对照。不要以继续增加提示词、审批或专用协议代替可运行的工具。
