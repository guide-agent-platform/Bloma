# Bloma UI 修改稿：画布优先、直接交流、动作可验证

日期：2026-10-11。核对源码：sprint2 / 06f4e90。依据用户截图和本轮源码检查。**本轮仅设计稿和独立交互原型，未改renderer/main/preload源码，未运行构建、打包、Electron或真实项目。用户正在继续测试现有实例。**

## 一、问题判断

现在的排版不适合复杂草图。截图里并非所有位置都密集：大量空间被固定宽度、小标题重复、巨大空态占用，而真正需要空间的草图和消息又被限高限宽。上一版把旧组件放进新外壳，未逐项检查它们在新布局下的尺寸、信息层级和交互。

源码确认：

| 问题 | 已确认入口 | 影响 |
|---|---|---|
| 草图画布固定偏小 | `theatre.css`：main最大880px、product最大720px；底部讨论固定占高 | 2560px窗口仍只用中间一小块；三栏草图被迫挤压 |
| 讨论受限 | 消息区域最大110px；展开历史抢48vh | 当前回复容易被裁切；读历史继续压缩产物 |
| 同一状态多次重复 | Shell场景大标题、Delivery大空态、MvpStatusBanner、消息区 | 没有增加行动信息，浪费高度 |
| 假“短回复” | `CompactReply.tsx`：长文取首段/140字，加details | 用户看到的简短不是模型真正清楚表达，全文仍长，可能省略关键限制 |
| 宿主指令冒充用户话 | `agent-loop.ts`将宽限轮宿主反馈落为role=user；ChatPanel依role呈现 | 截图绿色气泡含“收口指令/grep”，还出现重开按钮 |
| 复制无反馈 | `ChatPanel`可选navigator.clipboard，catch后静默 | 缺API/权限/写入失败都看似没反应；尚未实测本机具体剪贴板失败原因 |
| 重开无反馈、语义不完整 | `App.handleForkFromMessage`失败return，无catch；成功只换session/load历史 | 不启动续跑，不恢复对应制作阶段/文件版本；表面可能与原界面一致 |
| 图标未覆盖全部入口 | 大部分icons已使用Lucide；重开仍是Unicode箭头和胶囊文字，若干按钮仍为纯文字/旧样式 | 新旧视觉系统混用，不能声称已整体完成 |

上述从源码确认的处理缺口不等于已经复现每一个真实IPC/剪贴板失败。实施后需真实按钮流程验收。

## 二、布局改稿

### 主结构

1. 顶栏：48～52px，品牌、当前项目/切换、模式、设置。删除额外居中的品牌/标语。
2. 阶段导航：32～36px，用一个来源表示当前阶段，过去阶段可回看，不用点击未来阶段直接跳过确认。
3. 主工作区：窄资料导航 + 弹性画布 + 可收起讨论。取消880/720px固定上限。
4. 画布工具条：单行标题、当前版本、适应画布、专注预览。主确认按钮在画布下缘，始终可见。
5. 讨论默认完整显示当前自然语言消息，不按“最后一条user”粗暴筛掉其他轮次；历史有独立区域，不挤占当前草图。

讨论默认宽度约320px，可调整280～400px；程序画布使用剩余宽度。它是产物优先的工作区，讨论可以收起，不能再出现两个同等体量的聊天/预览磁贴。原型宽度受对话内展示约束，讨论初始286px；正式桌面值按实际可用工作区调整。

### 草图视口

- 草图按生成时声明的设计视口渲染，如1280×800；“适应画布”缩放整体预览，不能强迫原草图因容器小而把三栏挤成不可读。
- 有“原尺寸”与“专注预览”入口。适配比例过小无法辨认时，明确推荐放大或专注预览；不把字无限缩小当响应式。
- 点选标记坐标必须用缩放比例反算；缩放、浏览器缩放、滚动后都要核验位置，不能只看外观。
- 草图内容本身滚动与平台页面滚动区分；禁止整页、画布、聊天多层相互抢滚轮。正式工作区外壳固定窗口高度，各必要内容区各自承担滚动。
- 桌面产物通过独立窗口启动。制作中展示已确认草图；交付后可显示截图/操作入口，不伪装为真实原生桌面嵌入。

### 窗口适配

| 工作区尺寸 | 行为 |
|---|---|
| 1920×1080及以上 | 画布优先占剩余空间，讨论约320～360px；复杂三栏草图可展开 |
| 1366×768 | 压缩导航与周边空白，不缩小字号；主画布获得主要高度；讨论可收起 |
| 1024×700 | 讨论不长期压缩草图为窄栏，可进入独立抽屉/底部区域；专注预览一键进入 |
| 更窄窗口 | 画布/讨论作为不同视图切换，不硬塞双栏；核心操作和错误提示都可触达 |

移除“你的一句话正在成形”“停一下也没关系”这种常驻大标题；情绪化安抚不是状态来源。仅保留一条具体状态，例如“制作暂时停止，已有界面和文件保留”。旁边给“继续制作”和“调整要求”。不能只写“需要你来决定”而不给决定选项。

## 三、让模型真正讲短而易懂

撤掉用CompactReply折叠模型长文的默认策略；正文应直接呈现用户需要的信息。**不把大段输出直接截断，不从内部长文机械取前140字。**

分两个信息通道：

- 面向用户：本轮做了什么／结果和重要限制／下一步或一个明确问题。一般2～3句、约60～120个中文字符是软目标；有必要的约束或风险不能为凑字数删掉。
- 工作记录：工具结果、技术分析、阶段拒因明细、委派书、思考、控制协议、原始长输出。保留可追溯性，入口为“工作记录”，不作为聊天正文。

过程不需要模型每次工具调用都讲一段英文分析；阶段状态由宿主生成短中文状态即可。模型应从任务书、实际生效的覆盖提示词、普通轮/续跑/拒收/交卷轮四个入口得到一致的输出契约。只有一句prompt无法覆盖所有路径。

如已有输出过长：优先让汇报轮根据结构化事实写一次短用户摘要，长证据留工作记录。摘要过程失败时显示可核实的简短宿主状态并保留详细记录；不拿“已完成”代替未知结果。避免对每个流式片段都新增模型请求。

| 场景 | 正文示例 |
|---|---|
| 草图生成完 | “草图准备好了：左侧输入材料，中间看方案和参数，设备图随方案展示。可以标记要改的位置，或确认后开始制作。” |
| 正在制作 | “正在接通参数修改和方案保存。界面已确认，可以先回看。” |
| 暂停/受阻 | “已有界面和文件保留，上次检查没有完成。你可以继续制作，或先调整要求。” |
| 可试用 | “本地方案、参数修改和保存已检查，可以试用。模型增强还未验证，建议先用本地演示。” |

保留对话历史是保留之前的用户交流，不是把当前回答的冗长当成可折叠的合理输出。

## 四、内部消息与历史迁移

role=user不等于“用户亲自输入”。新增并贯穿存储/事件/renderer的origin或visibility标记，区分用户输入、宿主控制、委派内部交流、用户可见摘要。SDK为兼容而使用user角色时，仍须标记宿主来源。

宿主的收口反馈、拒收续接、session-recall、推进协议不可进入正常气泡，也不可提供“从此处重开”。历史没有标记时，只对已知控制注入格式作兼容识别；用户亲自引用技术文本不能被盲目过滤。保留原始JSONL，展示与模型上下文分开处理。

明确上屏排除：PHASE_ADVANCE、tool_use/DSML、内部工具名、宿主轮数/停用指令。存在真实故障时，转成具体用户状态，技术明细仍可查看。

## 五、复制和重开必须兑现

### 复制

使用受控Electron clipboard.writeText通道：shared契约 → main IPC → preload → renderer。验证文本类型/长度并返回明确成功或失败；浏览器原型可用浏览器剪贴板，但不能把其成功当Electron已验。

复制对象是当前用户可见正文，去除控制协议，不复制诊断或折叠摘要拼装件。按下后按钮短暂显示线稿Check和“已复制”；写失败显示“复制失败，请重试”及可定位错误。保留文字选择与Ctrl+C。取消catch静默吞错。

### 从此处重开

先明确动作范围：

1. **保留当前程序，重新讨论**：新会话从真正的用户消息建分支；允许编辑该条要求；提交后走正常接收/运行链。成功反馈“已新开讨论分支，当前程序保留”；失败保持原会话和草稿，不静默切换。
2. **恢复当时程序版本后重做**：只有存在关联快照才可选，说明文件/阶段的影响，通过版本恢复链处理后续确认。缺快照时禁用并写明原因。

不能让一个按钮只fork聊天，却暗示已经回滚程序或自动重新生成。仅在真实用户输入上提供入口；图标使用GitBranch/RotateCcw线稿，不使用Unicode箭头或永久紫色胶囊。色彩随项目模式。

异步过程有pending、防重复点击、成功反馈、错误反馈。当前运行时要显示忙碌原因或先停止选项；不能把BUSY、锚点缺失、IPC异常吞掉。不得使用projectList[0]兜底选择错误项目。

## 七、实施与验收清单

实施拆分为：消息来源/短摘要与复制/重开真实接线 → 主工作区尺寸与预览视口 → 旧确认/资料/设置组件统一。每批都查到实际消费点，不只改新外壳或新增未接入组件。

必要验证：

1. 用户截图项目、复杂三栏草图、2560/1920/1366/1024窗口，常用DPI缩放；确认按钮与输入始终可触达，草图不被720px上限挤压。
2. 草图生成/制作/暂停/交付/重开历史，各状态只出现一个清楚的主状态；制作中保留确认草图。
3. 真模型普通轮、续跑、拒收、交卷轮的正文均短且易懂；内部注入不出现在气泡；长证据可在工作记录查到。
4. 真Electron点击复制后外部粘贴得到同样正文；强制错误时有反馈，不声称成功。
5. 真用户消息重开：正确项目/锚点、新会话切换、接收回执、真实运行或保留编辑草稿；故障/BUSY无静默丢失；宿主消息无入口。
6. 从版本恢复确实恢复相应文件与阶段，不与只重开讨论混用。
7. 图标逐屏检查，不只检查icons文件；键盘、tooltip/aria-label、焦点和触达区域完整。

本轮原型的状态切换、复制反馈、重开分支、草图按钮均为本地演示，不执行真实模型、剪贴板写入、项目fork、文件回滚或程序启动。视觉检查不能证明上述真实接线已修复。

原型：本聊天可视化目录 `bloma-ui-revision.html`。独立无头浏览器检查通过：三栏草图、草图/受阻/交付3状态×1024/736/520/320px共12组宽度检查；可见控件不越界；专注预览实际增加画布宽度；历史、资料、复制反馈演示及重开编辑区可操作；页面异常0。证据 `ui-revision-checks.json`、`ui-revision-sketch.png`、`ui-revision-focus.png`、`ui-revision-paused.png`、`ui-revision-delivered-purple.png`，检查脚本位于仓库忽略目录 `run-artifacts/check-ui-revision.mjs`。本轮没有平台构建或真实GUI/IPC验收。源码基线保持06f4e90；本修改稿待用户评审后再实施，不构建用户正在测试的程序。
