# 测试工程支持与验收边界调整（2026-10-28）

起点：`sprint2 / 3dae2ac`。用户认可单模型持续执行、平台提供可靠执行/验证服务的方向，要求继续完善 harness 和平台支持。本批依据学习助手两轮失败记录处理测试工程负担，不增加 PRD、规划或第二模型前置阶段。

## 调整后的边界

开发脚本、无关探针继续由模型自由修改，用 `inspect_app` 调试。正式检查保留用户确认目标、已有业务案例的输入/断言和影响预期的公共逻辑，但不再因“文件恰好位于 tests 目录”就把它当作正式契约。允许保留原案例并追加检查；宿主确认测试尚未开始，或只有零断言的引导失败时，允许有凭据、有前后版本记录地修复草稿。真实业务断言失败不授权降低预期。

测试由同一个生成模型编写时，宿主独立运行它仍不等于独立设计验收标准。无交互、无有效断言、跳过案例、旧版本通过凭据或缺少能力证据，继续不能构成交付 PASS。已有第二模型独立设计保持可选，本批没有模型调用。

## 实现

### 1. 只准备实际引用的输入，并保留工程布局

- `native-test-inputs.ts` 从入口递归发现静态 import/export/require/import() 的本地支持模块，以及直接用于文件读取的 `new URL(..., import.meta.url)` 资产。缺失文件/包在规则发布之前返回具体文件和模块名，不再等完整验收结束后只报“案例未执行”。
- 无法静态推出的资产可选用脚本同目录 `native-inputs.json`，格式 `{ "files": ["工程相对路径"] }`。这是按需补充，不要求每个项目增加清单；代码不会执行测试模块来猜依赖。任意动态 JavaScript、TypeScript 运行时或所有 Node exports 条件不声称已被静态验证。
- 保留单文件 8 MiB、总 32 MiB、1000 文件上限；拒绝越界、链接输入和非法路径。原生方案增加 `layout: "project"`，文件路径相对工程，旧格式继续可读、可验。
- 每次实际执行在宿主拥有的工作区创建新目录，复制不可变输入并保留 `tests/…`、`tools/…` 等相对关系。通过受控 node_modules 链接使用当前候选的依赖，使标准 CommonJS 和 ESM 查找正常工作；不改写用户测试源码，也不复制另一版本依赖。
- 执行前后校验输入字节、路径及依赖链接身份。仅解除自己创建且身份仍匹配的链接，不递归清理链接目标；原快照和诊断输入保留。候选、依赖、范围及宿主版本仍绑定实际通过凭据。这不是 OS 沙箱。

### 2. 允许合理迭代，拒绝静默降标

- 登记比较保留原业务案例和支持逻辑，允许追加检查、定位和原有有界等待适配；不要求新增检查时再次确认用户目标。
- 无关探针不在依赖闭包中，修改或新增它不会改变正式套件的封存身份。正式注册仍会检查原有业务案例是否被删除或改写。
- 原始目录布局与新工程布局按源路径比较，简单旧规则可以兼容迁移。旧版全目录规则若含额外已冻结输入，不能证明无关时仍保守返回差异，不自动删除历史证据或改写真实规则。
- `GUI_EXISTING_EXPECTATIONS_CHANGED` 附具体案例/支持文件路径；已接受修订记录 previous/current digest、changes 和规则版本，旧快照不覆盖。
- 宿主凭据记录 native_plan 的套件哈希及 not_started/attempted。安全检查等在 GUI 开始前失败，不再永久锁死尚未执行的草稿；进入核心检查后按 attempted 保守处理。已有零断言引导修复例外继续绑定完整、未损坏的凭据与准确套件哈希。
- 测试加载失败保留实际 bootstrap 错误（例如缺少哪个模块），返回 `GUI_NATIVE_BOOTSTRAP_FAILED`，与业务断言失败分开。

### 3. 把平台杂务移回平台

- `verify_app` 在封存和准备发布副本之前，先检查正常入口是否匹配已确认的 desktop/browser/command 形态。开发观察仍可用于原型，不因此增加用户确认阶段。该检查与最终核心验证、独立试用共用相同的形态判定。
- 模型明确指定新的 process_id 且没有同时固定旧 debug_session_id 时，平台先验证该服务属于本项目/本会话、已就绪、源码匹配且数据目录明确，再关闭旧调试窗口并连接新服务。旧借用后台不被关闭；未知、他人、旧源码服务和明确冲突的 session/process 配对仍拒绝。
- 宿主附加的诊断截图使用有界捕获，失败单列 screenshot_error/evidence_warnings，不丢弃已经获得的业务断言。没有截图时明确不具备视觉复核证据；测试脚本主动要求的截图及其断言仍正常执行，真实渲染错误仍会失败。
- 模型入口覆盖错误列出 required/declared/missing/unknown F 编号，缺少入口登记也指出对应需求。实际客户端探针和真实 AI 效果的证据边界不变。
- 工具描述和公开 verification-gui 上下文同步上述规则，模型无需读取宿主源码猜恢复协议。
