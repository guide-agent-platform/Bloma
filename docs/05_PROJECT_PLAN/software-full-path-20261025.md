## 对旧设计的修改

1. 软件运行时使用宿主选择的local-software安全策略。正常child_process、参数数组、HTTPS不再沿用旧网页服务的整模块禁令，也不强迫成品调用平台/api/llm。JS/TS实际语法和词法绑定用于发现动态shell、eval/Function等问题，保留敏感信息和其它实际危险项。默认旧网页策略及历史工程行为保留。它是有边界的源码检查，不是全程序安全证明或OS沙箱。
2. 主Agent新增verify_app，直接得到具体失败步骤、实际/预期、CLI stderr与报告入口。主动检查和最终软件交付调用同一个验证器，避免两套验证漂移与重复运行。失败、取消、输入损坏先废止旧凭据；恢复旧源码也不能复活此前PASS。只有同一宿主进程、同一请求/操作、五分钟内完整通过且全部输入未变时可复用。
3. 凭据绑定源码/依赖/二进制全量摘要、确认目标、外观、GUI/CLI规则、实际冻结输入字节、解析后的入口/环境/运行时和验证器实现。最终仍复核候选与源文件，交付发布指针才指向实际通过版本。Python/硬件语音、无法完整绑定的外部执行参数及外部资源警告不启用复用。
4. inspect_app默认连续复用本会话的实际实例，源码变化自动重载，测试数据保留。显式once才新建一次性现场；restart真正重启后端/窗口并保留数据。指定不同process_id不会静默操作当前窗口。连接已有服务时，输入文件及文件断言也使用该服务实际APP_DATA_DIR，关闭调试不删除借用服务的数据。返回有界的真实DOM控件/当前值与新增错误日志，输入框优先，不强迫模型猜选择器或重复阅读大量项目路径。
5. GUI动作可用selector加has_text按记录可见身份定位，避免列表排序后nth-child误选。规则与回归基线继续固定输入/业务预期；只允许修复定位。正式验收仍要求真实断言，开发调试可仅执行动作或重启。失败明确返回actual/expected，不能把定位修正说成预期改变。
