## 上游参照与适配范围

上游已采用 Pi runtime，`pi-agent-adapter.ts` 保留应用SDKMessage协议并把实际执行交给会话运行时；`agent-runtime-guards.ts` 统一限制后续prompt/工具；`agent-collaboration-tools.ts` 把委派作为普通工具且保持调用幂等。

## 实施顺序

1. 桌面生产默认采用直接执行的主Agent，取消常规开发“必须委派才可落盘”的限制；保留项目路径隔离、阶段推进和独立宿主验收。实验冻结策略继续使用原实验面。
2. 对主/执行子会话统一处理无进展、重复读取及继续会话成本，避免新建执行者不断重新通读；父子调用共享可解释的运行预算。
3. 修复挂起PRD确认的自然语言入口，确认不得误触发整份需求生成与重新内审；负面和修改意图不能误确认。
4. 针对真实失败机制做可执行回归，再运行类型、构建、受影响测试与适当全量验证；提交相关改动并记录结果。

## 实施结果

### 主执行与成本边界

- `production-agent.ts`：常规 arch/scaffold/implement 默认由主Agent直接读、改、跑、修；独立验证仍由宿主与只读验收链控制，冻结实验保留原调度面。
- 架构入口提前物化既有骨架，不再把缺少平台文件当成重新研究起窗/线程/桥的理由。只对新增业务风险做专项实测。
- 同阶段续跑保留近期完整工具对，旧阶段/旧需求不混入本轮验证权威。完全相同的重复读取只从模型上下文省略，原始会话记录保留。
- 执行者6轮无有效修改/执行时提醒，24轮停止空转；失败写入不冒充进展，等待独立子任务不误算只读失速。策略只用于新生产执行范围，不污染冻结实验。
- `production-budget.ts`：同项目需求范围持久累计256次模型调用预约/重试、262144输出tokens保守占额，单响应最多16384；架构/骨架/实现/验证分别最多64/32/160/64次。取消或缺用量不清零；请求预约计数不是供应商物理请求账单。
- 每次阶段运行时限分别为8/5/30/15分钟，用户停止仍优先。脚本12次与安装4次由同阶段主/子执行者共享；跨阶段分开，续接与换执行者不重置同范围额度。
- 预算记录位于宿主`harness-budgets`，不包含提示词、密钥或业务源码；既有人民币策略仍独立生效，本批没有把token上限当成人民币上限。上述默认值是工程保护上限，尚未用真实产物试验标定最优值。
