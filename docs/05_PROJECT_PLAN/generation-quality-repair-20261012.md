# 软件生成质量修复（2026-10-12）

依据：software-generation-quality-audit-20261012.md 的 GQ-01～07。保留原记账、改名与工艺产物及其历史报告；不调用付费模型，不采集麦克风，不推送 Git。

## 批次一：需求与验收关联

- 新建 PRD 的验收文本由宿主绑定到功能项 id 与原始描述；读取侧不替旧数据补造绑定。
- 内审修订不再无条件继承旧 acceptance 与文档章节。描述改变或追加时，只保留经过绑定且身份未变的旧内容，其余从本项新断言投影，长文重新投影。
- 需求加厚禁止按相同编号继承不同描述的旧故事、断言和优先级。
- 桌面任务书携带逐项验证版本；关联不可信的历史文本与长文不注入实现上下文，保留当前描述、断言和问题说明。历史文件不回写。
- 已确认范围与实现排序分离：全部确认项属于交付清单，优先级缺失不等于可以漏做。

验证：6 个相关测试文件 101 项通过；类型检查通过。复现 F-004 从参数编辑变为真实模型增强，旧参数断言不能跟随编号继承。绑定用于防版本错位，不是语义裁判；它不能证明模型最初生成的验收内容正确，也不能单独证明实现完成。

## 批次二：逐项完成与模型请求证据

- 新验收声明 CORE_CHECK schema 2 分别记录全部确认项的实现状态与验证版本；宿主独立回读测试结果。不再只强制 P0；缺优先级、P1/P2、partial/missing/unverified 不能被其它测试的绿灯补成完整交付。
- 版本不符在运行脚本前拒绝复用。旧 schema 1 可诊断执行，但没有逐项声明与版本时不能认证新一轮交付；旧交付状态、文件与历史报告不批量改写。
- 内置真实 HTTP 客户端 llm_client.py 与宿主 llm_entry_probe.py；登记产品实际业务入口，使用拥有的本机 HTTP 服务验证请求参数、真实响应、401/404/429、非法响应与无 Key。测试默认阻止向其它地址连接，采用假 Key，不消耗模型额度。
- 固定 network_error、mock-only 响应在该探针下失败（请求次数为零）。端点不兼容/入口不可执行为 environment_blocked；请求能力与外部模型的生成质量分开描述。
- GUI 保留显式独立入口登记，GUI 场景不能借逻辑脚本同名输出取得证据；没有登记不会凭文件名推断 GUI 已测。

验证：5 个相关测试文件 25 项通过；4 项 Python 测试用真实子进程和本机 HTTP 通信通过；类型检查通过。模型探针证明登记入口的协议行为，不证明代理没有登记测试替身，也不评判外部生成内容的专业质量。人工审查/独立业务反例仍需保留。

## 批次三：文件状态、事务组件与模块组织

- 内置 file_transactions.py：预览带源文件元数据快照；执行校验当前目录、前缀、源文件变化、目标冲突及路径边界；不覆盖目标，异常回滚到原名，成功生成可撤销记录。
- 回滚受并发写入阻止时，保留原数据并报告 recovery 路径，不覆盖外部文件、不声称全部还原。进度回调与文件结果分离，通知异常记 warnings，不能触发错误回滚到新名称。
- ui/preview-state.js 绑定输入与扫描版本：输入变化失效、旧异步响应不重新启用执行、执行前消费一次防重复。组件自动物化，任务书要求接入实际业务；仅复制文件不等于功能已修复。
- 参数式前缀改名的宿主探针增加源文件变化与新目标冲突，共七项；支持明确 ok:false 的安全拒绝。拒绝结论仍以实际文件保持为依据。
- 框架保留三层职责，取消“所有业务/持久化必须塞进 app.py”的限制。复杂业务可拆领域/存储模块，app.py 保留 Logic 导入/门面与既有启动、驱动、自检、纠错协议。架构文档须同步实际模块和存储方案；轻量项目不强制拆分。

验证：4 个相关测试文件 29 项通过；Python 全套 25 项通过，其中事务八项包括准确字节往返、执行异常回滚、重叠文件名、通知异常、回滚受阻、撤销冲突及模块化业务入口的七项宿主反例。DOM 测试验证输入变化、过期响应、程序化改值与一次消费。类型检查通过。组件不保证断电原子性或隔离外部进程；真实生成质量尚待额度恢复后的对照实验。

## 收尾复查：验证期间变更与展示

- 核心验证结束后重新读取位于产物目录外的 PRD；源码、行为、全局体验/形状/能力契约变化使本轮证据作废。逐项版本包含这些行为约束；纯优先级变化不会改变逐项验证版本。
- 交付通知展示也核对当前源码与需求指纹；旧报告不再取得当前“已验证范围”标签，原报告不改写。
- 内审模型的断言、故事、范围和优先级字段先做结构校验，非法输出拒收而非在关联阶段抛异常。
- 全量回归发现 desktop-route 达到 801 行、触发现有架构规则。按职责拆出 delivered-notice.ts，保留路由负责阶段推进，通知模块负责证据展示；不增加超长文件白名单。

复查验证：6 个相关测试文件 80 项通过（含路由、架构规则、需求身份、核心验证与通知反例）；类型检查通过。最终全量回归与构建另记录在本文件末尾。
