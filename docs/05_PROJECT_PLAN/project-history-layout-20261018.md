# 项目回访历史恢复与工作区布局

2026-10-18。用户反馈：离开项目后返回，对话、协作与工作记录缺失；草图和聊天上下挤压。

## 原因

- 回访只读取 last_session_id 对应的单个 JSONL，且仅保留末尾 200 条。连续制作已切换主会话时，原始需求还在其他主会话磁盘文件中，却没有回填。
- ChatPanel 的剧场模式默认只展示最新回复，每次会话切换重新折叠。完整对话正文被限高为 225px，默认正文仅 118px。
- 协作状态只从实时 delegation 事件归约，重新挂载没有历史恢复链路。工作记录又复用了当前单会话消息并再截断 200 条。
- 上下堆叠的预览与聊天竞争窗口高度；放大草图无法补救聊天空间不足。

## 本次修改

- agent:load-messages 增加可选 include_project_history；默认单会话行为保持兼容。回访合并同项目连续主会话，按时间排序、按消息/客户端 ID 去重，携带 source_session_id。fork 分支仅恢复自身已继承的前缀，不与替代讨论混合；回看旧需求时“从这里新开讨论”使用其真实源会话。
- 首次恢复发现 truncated 后，按实际 total 补载。IPC 回包与正在接收的消息合并，保留回包期间的新消息和协作终态。
- 从同项目关联子会话（含嵌套）恢复任务、角色与终态；取消 settle 优先于索引状态；没有终态的历史任务显示“状态待确认”，不凭索引 active 宣称正在执行。
- 默认展开连续交流；工作记录使用全部已恢复消息。
- ≥1100px 窗口：左侧 370px 对话，右侧全高草图/程序，底部保留必要状态。对话与预览各自滚动；未有预览时以对话为主。窄窗口切换“对话 / 草图与程序”；保留专注预览、文件/说明折叠和项目资料抽屉。

上游参考：本地 proma-upstream bf3e98c，agent-active-session-snapshot.ts 的“旧快照不能覆盖较晚运行态”原则。本次适配到历史消息及协作回填，没有移植上游完整 session 协议或修改模型上下文存储。
