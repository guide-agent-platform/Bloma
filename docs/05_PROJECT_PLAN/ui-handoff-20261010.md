## 用户的审美反馈与当前方向

### 当前界面的观察

实际启动后看过平台主工作区与模式选择页；开始恢复的是旧网页计算器项目，其右侧计算器属于旧产物，不能把它当作现行平台整体设计。

- 浅色底与紫色有亲和力，但 aurora、玻璃、阴影与大圆角叠得多。
- 入口品牌标志/留白占据较多高度，模式选择与主要按钮被推到下方。
- 顶栏与状态横幅重复，工作空间受到挤压；页面和局部面板有多层滚动。
- 品牌衬线字、胶囊按钮与默认 Electron 英文菜单的气质不够统一。
- 新桌面项目空状态出现“缺少 LAUNCH.json”，工程提示不适合普通用户默认体验。

### 已获认可的第二版设计主张

让用户感到：**自己的一个想法逐渐成为一个真实的软件**。

- 一句话输入成为入口中心，快速/长期以轻巧、清楚的方式选择。
- 同一个程序窗口/产物对象贯穿需求、草图、制作与交付，维持视觉连续性。
- 程序成为工作区视觉主体；对话、文档、材料、版本和协作根据当前任务展开。
- 趣味来自操作联系：确认草图后自然进入制作，完成后主要操作自然成为“启动程序”；按钮按压、保存反馈、展开方向有细腻反馈，避免持续抢注意力的装饰动画。
- 上一条助手提出的具体摆放方案：底部对话输入、侧栏提供文档/版本/材料/协作。这是可调整的设计探索，不是用户锁定的位置要求。

用户原话授权：“基本的要素还是要有，位置你随便改，放开手大大方方干”。不再用现有双栏和卡片布局作为设计上限。

## 基本要素必须保留

1. 项目列表、新建、当前项目名称，快速/长期选择与既有升级语义。
2. 对话历史、输入、发送、附件/历史材料、语音、等待与停止、接收回执和恢复语义。
3. 需求/PRD 确认、UX 草图确认与点选纠错、长期模式 MVP 确认、交付后纠错。
4. 产物/草图预览、桌面产物文件、启动、导出、交付状态与可解释的空态/失败态。
5. 文档、协作、版本记录、当时文档回看、回滚。
6. 模型渠道/设置入口与必要状态反馈；不向 renderer 暴露 Node、文件系统或密钥。

布局可以重构，不能为了画面简洁删掉能力、跳过确认或把“正在制作”当成“已经验证”。入口如果新增先写想法，落地时必须接好项目创建、草稿和首次发送身份链；仅把文字传给 createProject.initial_message 不等于消息已发给 Agent。

## 运行与工具注意事项

- 项目未封包，标准入口 **`npm start`**（build → electron .）。Windows 窗口枚举能看未封包应用，前提是已启动。
- 本轮工具沙箱内 npm start 在 esbuild 创建子进程时报 `spawn EPERM`；沙箱外成功。启动时清理 `ELECTRON_RUN_AS_NODE`，避免 Electron 被当作 Node 运行。不要把环境限制误当源码启动缺陷。
- 曾启动过标准 npm 开发实例，统一 exec session 为 `35107`。是否仍运行须接手时重新检查；不要复用旧窗口 ID/坐标，也不要强杀用户正在操作的实例。
- 读 Windows GUI 使用 computer-use 技能与 node_repl 的 `@oai/sky`。先读完整技能和 guidance/confirmations，再按返回窗口对象操作。用户会同时切窗口/操作，工具曾返回 bounds changed、minimized、user input detected，截图也曾混入前台聊天窗口；不据此图评价 Bloma，不对错误窗口输入。
- 可视化原型用 visualize 技能。**Reload the full visualize skill before creating or updating a visualization.** 使用上述线程可写目录，片段不写完整 HTML 文档，不改用户实际 GUI。
- 本地检查调用 `visualize/scripts/render.py` 生成独立检查页；覆盖同名检查页加 `--force`。iframe 内操作要选择其 frame。
- 明暗切换和按钮有约 140ms 过渡，截图要等待过渡完成；此前暗色选中态抓到中间帧，看似错色，稳定帧与颜色断言均通过。
- 参考苹果的材质语义与内容/导航层次：https://developer.apple.com/design/human-interface-guidelines/materials 。不照搬假 macOS 标题栏或 Windows 不支持的交互。
