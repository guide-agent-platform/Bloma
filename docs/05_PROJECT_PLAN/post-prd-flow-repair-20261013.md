授权：用户在 [后流程核查](post-prd-flow-audit-20261012.md) 后要求修复，并要求继续。基线 d258b3f。本批保留静态外观草图与原 quick/longterm 分支，不重建交互原型平台，不修改历史生成产品、真实渠道或提示词覆盖文件。

## 已实现

### 设计信息进入 UX

- UX 输入现在包含完整已确认 PRD，包括对象、流程、业务规则、验收场景、约束与来源。
- 新增轻量 `UxDesign`：页面、流程关联、用户动作、正常/边界/异常反馈、场景关联，以及有具体原因的非界面职责。全部需求/流程/场景必须得到说明，未知编号、错误状态类型、遗漏场景均拒绝。
- 同一次模型调用产出设计记录和静态 HTML；结构化输出协议追加到实际覆盖后生效。HTML 对应真实页面/交互元素标记，注释/文本中的假标记不能替代元素。空 HTML、脚本及事件属性不作为有效静态草图。
- 首次生成失败仍可提供如实标注的机械简易方案，保留全部需求与反馈状态。预览失败时显示可过目的文字方案，而不是只有四个按钮；文字确认不沿用残留旧 HTML。

### 调整意见与确认控制

- 无论是否存在上一版摘要，用户意见都进入下一轮提示词；正常调整携带上一版 HTML 和设计记录。失败的意见保存到 pending，重试仍使用原意见，不用“重试”覆盖实际内容。
- “不要开工”“取消开工”“不确认，先调整”“不要按草图”等否定指令不触发开工；“不需要调整，可以开工”“不用再改，按草图开工”等明确认可不会被词语子串误伤。
- 明确暂停保留当前设计，调整轮次到达上限停止自动重画并重新展示选择。用户可明确采用或再调整一次；次数不构成确认。
- 模型识别为新增功能/改业务规则的反馈回到 PRD 整理与确认，再重新设计 UX；不能把新范围藏进旧 PRD 的草图。判断仍依赖模型，不能声称已证明任何自然语言都能正确分类。

### 当前需求、设计与停止信号绑定

- 绘制、调整与确认都核对当前 PRD 确认状态和需求指纹；生成过程中需求变化也不继续出旧版本确认卡。
- `confirmed.json` 记录设计和 HTML 哈希；项目目录外的宿主 Project 记录 `ux_confirmation` 的需求/设计/HTML 指纹。修改生成目录中的确认文件不能自行获得新授权；改变文字/HTML 模式也不能绕过 HTML 校验。
- UX → 桌面交接保留原 AbortSignal；已停止时不生成、落盘或出确认卡。归档回门同样透传信号。
- 桌面入口和每阶段重入复核已确认设计绑定， stale/缺失绑定暂停；工程角色收到确认 HTML 和设计 JSON 的路径与读取纪律。没有新模型的历史数据仍保留查看和原确认草图兼容路径。

### 架构与骨架检查前移

- 非 verify 阶段的真实收口在存在性检查后读取文件内容；空架构、非法 JSON 环境清单、无效工程契约、空驱动骨架不能推进到实现。
- 新需求模型的架构额外产出 `00_ARCH/architecture.json`，绑定 PRD 指纹，明确全部功能/规则的模块位置、业务对象的归属/留存/失败策略，以及各验收场景的验证位置。
- 工程契约前置登记当前 PRD 指纹与全部已确认 F 编号，不限 P0。骨架阶段可留待实现的断言，但不能自报测试通过。
- 任务书和子任务基底同步给出 JSON 协议、当前需求指纹和修复原因。quick 仍直接实现，未强制增加繁重的独立架构阶段；longterm 的 arch/scaffold 内容门按实际文件执行。
