# UX 创意空间与设计接收修复

日期：2026-10-17。实施基线：`d3229a9`，用户已授权确认路线后直接修复。背景与原始证据见[跟进方案](ux-creative-freedom-followup-20261017.md)。

## 已实现的行为

### 视觉目标与实现约束对齐

- 默认 UX 提示词改为接近成品的静态设计：先形成与用途相符的视觉主张，自主决定构图、字体、色彩、组件与项目 tokens。去掉灰阶低保真、固定线框、仿系统标题栏和产品内固定页脚要求。
- 仍保持静态 HTML/CSS、无模型脚本、离线资产、功能与验收语义不变。局部修订和用户明确要求的整体视觉重构分别处理。
- quick / longterm 实现任务书、已确认设计交接段、形状指引、骨架手册与注释同步开放布局和 CSS；项目 tokens 的值允许按设计重写和扩展。默认组件提供行为示例，不再把预置视觉当成产品上限。
- `App.call`、`App.show` 与 `.w-banner`、驱动/纠错脚本及定位标记保留；可以重绘状态节点，不删除行为接线。没有改桥、业务逻辑或平台验收门。

### 输出协议、路由与候选复用

- UX 门统一解析 `sketch` 类别；PRD 确认、改品类、归档回门和调整都进入同一解析点，仍尊重显式渠道选择。去掉两个入口额外的 PRD 路由解析。
- 新默认不再夹带“只输出 HTML”；宿主按有无背板明确选择 JSON 或旧 HTML 输出协议。用户自定义覆盖保留原样，宿主协议明确优先；已有覆盖如仍要求灰阶，仍会保留该偏好。
- 向结构化调用提供宿主从 PRD 提取的 F → 状态类型 → AC 索引，减轻编号关联负担。P/UI 由设计者分配，F/W/AC 仍来自 PRD，不重新编号。
- 第一次响应的 HTML 通过现有静态校验后，即使设计关联失败，也单独归档候选 HTML 和哈希。重试可只修正 `design`、省略 `html`，平台原样复用同次生成的候选；需要新增页面元素时仍可返回完整新 HTML。
- 复用不跳过需求覆盖、状态类型、页面及交互标记检查。含脚本的 HTML 不成为候选；关联仍错误则如实兜底。候选归档不进入确认预览，也不能直接冻结或开工；调整失败仍保留上一版及未处理意见。

### 运行证据

复用文档目录下的 `diagnostics/ux-design-attempts.jsonl`，新记录版本为 2：

- `generation_started`：生成器版本、运行 ID、会话、home、同一次读取的覆盖来源和哈希、装配后 system / user 哈希、请求模型和渠道、采样与预算参数。
- `output_checked`：输出哈希与截断说明、校验问题、是否可预览、是否要求修订需求、候选文件及 HTML 哈希、是否复用候选。
- `attempt_failed`：请求错误、空输出、解析/校验失败，或明确的超时 / 用户取消。终止原因由标准调用件的信号判定，不靠猜测供应商错误文案。
- `generation_finished`：LLM 结果、模板降级或调整失败后保留上一版；UX 暂存决策也记录生成运行 ID 和失败概要。

提示词来源与实际请求内容从一次读取获得，避免设置在生成期间修改后日志记录成另一份提示词。不复制整份 env 或供应商错误正文到新日志。

`requested_model` / `requested_channel_id` 是调用开始时请求的配置；运行时回退后的物理模型与费用继续以现有 usage-ledger 的传输回执为准，不把初始配置冒充最终实际路由。诊断写入失败不改变校验与确认结果。

## 后续边界

本次直接修复已确认与用户目标不一致的规则，同时保留可撤销的默认提示词与既有本地覆盖机制；这不代表已经完成原方案的 E0/E1 偏好实验。多候选搜索、图像输入和视觉评审闭环未自动启用，避免增加未经验证的调用与选择成本。

骨架物化继续跳过已有文件；构建完成不重写历史软件，也不自动重启用户当前的 Bloma 实例。新默认在使用本次构建的新运行中生效。

实现参考本地上游 `proma-upstream` / `bf3e98ca61dd8365eceaef876c0f7473700878a6` 的 `agent-prompt-builder.ts`：静态角色说明、动态上下文和宿主协议各自承担职责；本项目沿用自己的调用件、静态 UX 确认和桥接协议，没有搬用上游工具或运行时。
