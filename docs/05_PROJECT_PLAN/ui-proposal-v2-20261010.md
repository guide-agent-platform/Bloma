## 设计主张

让用户看见自己的想法逐渐成为软件。一个持续存在的程序窗口承载想法、需求、草图、制作与交付，成为工作区视觉中心。对话作为下方的持续陪伴；项目资料按需展开，避免一直占据主视线。

- 顶栏集中品牌、当前项目、项目切换、模式与设置。制作进度为一条可以回看的轻导航，未来阶段不可跳过。
- 主区保留同一个软件对象。需求时承载确认清单，草图时可操作，制作时说明当前工作，试用和交付时呈现启动、文件、导出、反馈入口。
- 当前确认动作靠近软件，向导最新回复、输入框与常用工具位于下方。完整对话可展开，普通输入不要求用户管理协作者。
- 文档、材料、版本、协作采用同一个按需面板；展开时让软件让出空间。窄窗口顺序重排，不覆盖主要确认动作。
- 快速型紫色、长期型绿色；浅色、深色均使用独立产品色值，跟随系统或显式切换。克制使用阴影与局部柔光，保留清楚的实体面。
- 趣味主要来自操作联系：计时器立即响应，点选明确显示对象，确认自然推进，同一对象持续保留，停止后可以继续。没有循环装饰动画。

本地上游核对为 `proma-upstream / bf3e98c`，查证入口为 `AppShell.tsx`、`LeftSidebar.tsx`、`ChatInput.tsx`。本轮没有复制上游源码；布局为针对 Bloma 确认门与产物工作流的新预案。材质参考入口为 [Apple Materials](https://developer.apple.com/design/human-interface-guidelines/materials)，本次文本抓取仅返回需要 JavaScript 的页面，不将未读取的细则当作已核对结论。

## 可以探索的操作

默认从专注计时器的“界面草图”进入，前面的需求与 PRD 视为示例项目已确认。点击项目列表里的“开始一个新想法”，可以从头体验完整流程。输入使用固定计时器案例演示交互，不执行模型生成。

| 能力 | 预案行为 |
| --- | --- |
| 想法与模式 | 一句话进入需求；入口可选紫色快速型或绿色长期型；已有快速项目提供升级说明与确认 |
| 需求与 PRD | 需求清单先确认，随后展开 PRD；PRD 独立确认后才进入界面 |
| 草图 | 时长、开始/暂停、记录/设置可操作；点选计时显示或开始按钮，再描述修改 |
| 制作 | 草图确认后开始模拟制作；停止不会自动推进，继续从当前演示步骤恢复 |
| 试用与交付 | 快速型可试用再确认交付；长期型必须确认 MVP；交付后提供启动、导出、文件和反馈 |
| 对话 | 完整历史、消息回执、从一条消息重新开始；Enter 发送、Shift+Enter 换行 |
| 材料与语音 | 材料加入/撤出草稿、历史材料再引用；语音用固定转写示例，发送前留在草稿 |
| 版本与文档 | 过去阶段只读；当时文档可回看；回滚先确认，保留回滚前计划，后续确认重新进行 |
| 交付后迭代 | 改进意见回到需求确认，保留上一版计划供查看 |
| 异常与等待 | 设计控制可切换接收失败、启动失败、等待回复；恢复草稿不自动发送；提供重试、反馈、继续等待与停止 |
| 设置 | 系统/浅/深外观选择、渠道入口反馈；不读取真实密钥或改写真实渠道 |

启动、导出、语音、消息接收、生成、检查与文件操作都为本地演示。版本保留是本次预案运行内的计划快照，不是平台磁盘快照与真实 Git 回滚。预案的“检查完成”不能作为生成程序或供应商已经验证的证据。

## 落地时的边界

1. 本预案只确定可探索的设计方向，等待用户评价后再决定最终布局；不要把它记为用户已经验收。
2. 落地复用现有 `WorkspaceShell`、`ChatPanel`、`MessageComposer`、`DocumentPanel`、`TimelinePanel`、`DeliveryPanel` 等业务语义与状态，保留 data-ai-id；不要用演示脚本替代实际接线。
3. 从想法入口落地必须处理项目创建、草稿归属与首次 chat:submit 接收链，不能只传 createProject.initial_message。
4. 草图属于嵌入预览；Windows 桌面程序仍通过受控启动路径打开独立窗口。预案里的同窗试用只是视觉演示，不能据此承诺原生桌面嵌入。
5. 保留需求/PRD、UX、长期 MVP 确认与错误恢复边界。运行状态、制作完成、验证结果、交付终态分开解释，不能靠动画推断完成。
6. 模式绿色需要覆盖现行长期模式的 cyan 引用；明暗对比、键盘、窗口缩放与真正 Electron 复验属于落地验收。
