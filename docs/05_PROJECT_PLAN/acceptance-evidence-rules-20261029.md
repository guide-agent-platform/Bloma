# 平台验收与交付规则：证据分层

基线 `09f14a6`。用户明确选择平台验收与交付规则，本批不修改已交付学习助手的业务代码，也不添加真实模型请求或新的人工确认阶段。

## 规则

1. **覆盖编号是关联信息。** 软件流程每项结果保留当前需求哈希及已登记检查的 verification；不再将 verification=passed 自动推成 implementation=implemented。兼容字段 implementation 保持 unverified，新证据层明确 implementation=not_assessed。历史标准流程已有声明字段保持原有验证方式，不迁移旧报告。
2. **本机行为与能力协议分别记录。** 每项 `acceptance_evidence` 分别记录 local_cases 和 capability_contracts。GUI／CLI成功不能覆盖所需能力检查缺失或失败；协议成功也不能抵消用户可见行为失败。
3. **验证器身份由宿主记录。** required llm／speech／prefix_rename 等能力必须有对应宿主验证器结果，并覆盖当前功能。registry 省略验证器、或无关验证器试图在返回值里伪报 verifier_id，均不能放行。麦克风等原有额外实测门保持。
4. **本机 HTTP 不等于外部效果。** 需求声明 llm，或实际登记在 llm.covers 中的项，external_model_effects 保持 unverified。当前没有可核验的供应商连通／模型质量证据接入，不能由本地替身、编号、步骤数量或B设计通过推导为已验证。
5. **明确交付范围。** 根报告 `acceptance_evidence` 记录当前已登记本机检查、覆盖来源、完整实现及完整需求未独立评定。工具回执、生产收口／里程碑文字、交付面板一致显示范围。本机通过后可按既有条件提供本机试用／交付；不把这一状态解释成完整教学效果通过。未增加付费补验或自动用户确认。
6. **失效时整层降级。** 目标／源码在验证中变化、收口失败或验证报告写入失败时，新证据层的本机通过、能力通过及 local_status 一并失效；不让嵌套的旧绿色字段存活。损坏凭据仍不能复用。
7. **历史未知保持未知。** 读取没有新分层字段的旧报告时，显示历史范围需核对，不倒推真实模型效果或完整需求通过，也不重写历史产物／状态。

新层级是对证据的解释规则，不是对语义充分性的自动证明。implementation=not_assessed 不代表已经证实没实现；它表示本机测试不足以签发“完整实现”的结论。按现行 local 分发提供程序与完整产品效果验收分开表达；如果未来要将外部效果作为交付硬门，需要单独设计、授权和可校验的证据协议。
