# 调度组中断审计与资源接线修复（2026-10-15）

四组续跑的G11启动后，发现两个会影响实验有效性的问题，已由Codex审计取消；G12/G21/G22均为0次模型请求。G11保留原生cancelled终态及原始输入、角色请求和产物，独立质量为null，不记模型能力零分。

## 已确认问题

1. 配置D40/E64，但 `resolveDelegationTurns` 用父调度员的40轮夹住子实现者预算，实际只有E40。中断样本的 `effective_resources` 和子会话提示“本轮上限40轮”均证实此接线。此前S1/S2直接实现实际E64，不能把这批调度组与它们宣称为相同执行预算。
2. 计划登记接受 `core/**`、`ui/**`，执行器只支持具体文件或以 `/` 结尾的目录前缀。首次委派锁定计划后，普通 `core/...` 写入被拒，规划者也无法再改计划。样本记录8次write_rejected及1次已锁定计划修改拒绝。这不是供应商API调用方式出错。

## 修复

实验宿主给implement角色单独设置child turn cap，并由相同解析函数提供实际循环预算与资源遥测。D40保留为父循环上限，E64可供子循环使用；其他未显式配置独立cap的调用保留原有父循环夹限。

新计划在锁定前拒绝含 `*` 或 `?` 的写范围，工具schema和内部实验协议明确文件/目录前缀语法。规划者可在首次委派前自行更正，不由宿主生成分解答案。旧配置读取仍兼容，避免历史含通配符的失败样本无法报告。
