# UX 候选探索与视觉反馈：生产接线

日期：2026-10-17。实施基线 `7e22498`；用户已明确要求落实机制。方案依据见[机制试验](ux-visual-selection-trial-20261017.md)。

## 新的默认行为

Electron 中的结构化 UX 门默认进入以下流程，quick / longterm 共用同一入口：

1. 根据已确认功能和实际生效的设计偏好，提出两个具有不同构图、操作表达或视觉语言的方向。
2. 分别生成候选。每份候选保留一次格式/关联修复机会，继续使用原有 HTML、页面/交互标记、F/W/AC 与需求指纹校验。无效候选不参加选优。
3. 在独立无界面浏览器进程中渲染两个窗口尺寸，阻断页面网络、关闭页面 JavaScript。优先使用已有 Chromium，失败后尝试已安装的 Edge；不自动下载浏览器。
4. 将实际截图交给当前设计渠道，分别评价视觉表达、基础操作可发现性和附加价值。所有候选和评审记录保留在项目内。
5. 对选中的候选最多做一轮视觉改稿，再对原稿和改稿做成对截图比较。最终比较只给 X/Y 标签，不提供修改先后身份。
6. 改稿不合格、比较失败、结果打平或新增横向溢出时保留原稿。完成后仍进入原 UX 确认门，不自动开始实现。

用户明确提出的调整沿用当前稿件，不重新探索两个方向；视觉建议不能覆盖本轮用户要求。无截图、渠道不支持图片、超时或额度不足时保留已通过校验的设计，并记录部分完成原因；没有可用模型稿时沿用如实标注的模板/文字降级。

普通 Node 调用、没有结构化背板的旧调用以及显式 `BLOMA_UX_VISUAL=0` 使用单稿兼容路径。这个退出开关只影响新生成，不重写已确认设计。

## 原始功能和附加能力

原始功能是交付底线，合理新增能力可以加分，仍需遵守用户明确的约束和范围外事项。

- `UxDesign.enhancements` 单独记录 E 编号、名称、说明和价值，最多 8 项，旧设计不需要补字段。
- 基础 F/W/AC 的覆盖、编号、类型和确认版本不放宽；新增 E 项不能替代原需求。
- 确认摘要和独立状态页明确显示附加能力是设计提案。用户确认的设计哈希包含这些字段。
- 调度员与实现子会话读取已确认设计中的增强，保留全部原始功能，并如实说明新增能力的实现和验证情况。
- 用户明确要求新增/删除必备功能或改变原有业务语义时仍返回 PRD 修订，不降级成可选 E 提案；模型主动提出的合理附加能力不会仅因初始短需求未提及而被自动拒绝。

## 状态说明独立呈现

主产品画面不再为证明覆盖而堆放状态示例卡。完整动作、正常/边界/异常反馈和附加能力仍保存在设计记录中。

`stageUxSketch()` 从已验证设计生成 `00_UX/ux-state-review.html`，与设计版本一同归档；通过既有项目预览协议提供地址。事件按项目隔离传给 renderer，预览新增“界面预览 / 交互与状态说明”页签。切换说明页不更换待确认设计、不触发开工，也不启用该页的点选纠错层。

状态说明由宿主转义生成，页面清楚说明它不属于产品主界面，文字状态不代表已经执行过测试。原来的用户确认、HTML 哈希、需求指纹和宿主确认凭据继续生效。

## 传输、费用与失败边界

- 所有规划、候选、图片评审和改稿共享同一个操作预算，最多 8 次实际请求的准入，单次输出上限 16384 tokens，整体视觉流程最多 240 秒；不能靠格式重试、HTTP 重试或渠道回退清零。
- 准入回调在每次物理请求及其重试前执行；拒绝不能作为普通遥测异常被吞掉。既有共享金额闸也仍在 HTTP 前执行。
- 优先使用显式金额策略，否则只读查找所选模型当前已激活的共享策略，不重置、切换或清空历史账本。存在有效费率时，本操作按配置费率额外限制 5 元；图片按完整上下文保守预留，已报告 usage 后结算，未知请求保留预留。
- 没有金额策略时明确记录 `monetary_control=not_configured`，只保证次数和输出上限，不把 token 控制称作人民币硬上限。金额策略损坏时阻止新请求。
- DeepSeek 带图请求采用其官方 OpenAI 图片格式；文字请求继续使用原 Anthropic 路径。现有会话图片水合、SDK 账本和流式协议复用，API Key 不进入新日志。
- 截图和视觉请求失败不冒充已完成评审，也不删除合格稿。取消会中止后续请求和截图，不发旧版本确认卡。

### 真实生产 UX 门

以同一句计数器功能需求，从已确认的最小功能 PRD 调用实际 `runUxConfirmGate()`，没有替换生产生成器、截图器或 SDK。没有继续发起桌面实现。

- 无界面渲染探针返回两个正确窗口尺寸，截图采样检测到 132 种颜色；没有显示 Electron 窗口，截图进程完成后已收尾。
- 成功复测完整执行：方向规划、两个候选、实际图片评审、一轮改稿和前后图片比较，共 6 次真实请求。
- 两次图片请求均发送 2 个非空图片块，实际 URL 为 `https://api.deepseek.com/chat/completions`；文字请求继续走 `/anthropic/v1/messages`。
- 本次进程没有设置全局 `BLOMA_MONETARY_POLICY`，操作预算自动只读复用已有激活策略，结果记录 `verified_policy`，没有创建新额度窗口。
- 成功运行 `status=complete`，最终选用 `refined`，按配置高峰价保守记账 0.109493 元，全部 usage 已报告。
- UX 确认卡保持待确认，独立状态说明通过实际项目协议读取得到 HTTP 200，主应用没有自动开工。

初次生产试跑因两个模型稿遗漏交互控件标记而退回模板，3 次请求、保守记账 0.063869 元；该失败保留在 `first-live-attempt/`。后续明确标记协议并保留候选的校验修复机会，未删除检查来制造成功。两轮生产试跑共 9 次请求、0.173362 元保守记账，不等于单次运行超出 8 次限制。

早期直接使用 Electron 窗口截图的本机探针出现错误/异常退出，尚未调用模型；已改为独立浏览器进程，相关日志保留。不会将这个原生截图路径部署为默认实现。

`result.json`、`transports.json`、`renderer-probe.json`、`events.json` 保存最终运行、真实图片块、渲染探针和确认卡证据；`live-refined.png` 是实际生产管线选出的截图。它们证明该简单任务的链路，不证明通用审美收益、最终用户偏好或真实程序业务功能。
