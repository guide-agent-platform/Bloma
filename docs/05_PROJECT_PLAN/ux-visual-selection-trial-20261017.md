# 计数器：候选探索、截图评审与一轮改稿试验

日期：2026-10-17；生产源码基线 `4818ba7`。用户授权尝试机制，本轮在隔离环境运行，没有将实验流程接入生产默认。

原始需求保持为：**做一个计数器，可以加一、减一、清零。** 用户未指定配色、字体、参考图或构图。功能 PRD 复用上一轮；平台仍自动提供默认产品设计提示词。

## 用户最新评价标准

用户在试验过程中明确：**多加功能可能是加分项，少了功能不会是。** 本次采用以下现行标准：

- 原始功能是必须保留的最低要求，不能用额外功能补偿基础功能缺失。
- 有用的附加功能与交互可以加分，不因为初始短需求没有提到就自动判为越界。
- 分别观察视觉表达、原有操作可发现性和新增价值，不把它们混成一个无法解释的总分。
- 设计提案中出现的新功能，在实现后仍需验证，静态文字不能冒充已经实现的能力。

初次方向提示中有“不添加功能”的保守限制。该限制已被用户此次澄清取代；没有修改历史请求或伪称已按新规则重跑全部步骤。

## 实际执行

1. 真实模型提出两个方向：A 为机械计数仪；B 为极简手势计数器。金属、黄铜、旋钮等构思来自模型，没有由执行者预先指定。
2. 两个候选都通过现有 UX 结构与适用场景关联校验。产品 HTML 只呈现主界面；宿主从各自 `design` 记录生成独立的 `A-states.html`、`B-states.html`，保留全部动作与状态说明。评审记录不是实际状态运行证据。
3. 候选、原先单稿分别在 1100×800、820×700 渲染。浏览器 JavaScript 禁用、网络阻断，产品 HTML 未手修；均未发现横向溢出。
4. 通过真实 DeepSeek Flash 图像 API 发送三张截图，要求基于可见区域比较并提出最多三项修改。传输记录确认请求包含 3 个非空图片块及其哈希。
5. 评审在本次候选中选择 A，建议明确旋钮操作、提高底部文字可读性、减少装饰性铭牌。整体排序仍将原先单稿放在第一，不能报告为新方案全面胜出。
6. 将具体意见交给现有 UX 生成器做一轮改稿，再发送改稿与 A 原稿的两张截图做成对比较。模型偏好改稿，主要理由是操作提示更明确。

第一轮比较告知了哪张是基线，只隐藏候选 A/B 的映射；不是完全盲评。第二轮只给 R/S 标签，没有提供修改前后身份。两次评审都使用同一个模型，不能将结果当成人类偏好或独立审美真值。

## 过程中纠正的判断

视觉评审建议引入“长按连续计数”，改稿也显示了该交互。执行者最初按过窄的范围标准将其拒绝，并额外发起一次仅删除该交互的修订。

用户随后明确附加功能可加分，因此撤回自动拒绝的判断：**本次保留 `refined.html`，即带长按连续计数提案的机械风改稿**。额外生成的 `corrected/counter.html` 仍作为更窄版本的对照保留，既不覆盖改稿，也不隐藏这次额外调用和费用。

`host-review-initial.json` 保存初始判断，`host-review.json` 记录用户澄清后的现行判断。后续机制应把“原需求必备”和“可增益的额外能力”明确区分；评审可提出新增能力，不得通过新增能力省略原有功能。

## 观察与边界

- 候选探索确实产生了不同构图与操作表达，机械仪表有明显独立性格；原稿中的状态卡也已移出产品主画面。
- 极简手势方案虽然保留功能描述，但桌面操作的可发现性较弱，说明独特或简洁不能单独代表优秀。
- 图像评审能引用旋钮、铭牌、底部状态条等真实可见区域，能提出局部修改；综合排序、选择理由和对新增能力的评价仍需明确口径。
- 这是一项任务的组合机制试验，基线来自此前单稿，没有分离候选搜索、状态分离和视觉反馈各自的收益。不能宣称审美成功率提高或已证实优于单次生成。
- 全部都是静态 UX，未实现点击、长按、声音、震动或真实桌面程序。方向文本中的物理触感设想不代表已经具备相关能力。
