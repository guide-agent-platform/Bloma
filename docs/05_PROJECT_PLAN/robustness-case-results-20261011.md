# 稳健性计划：六案例结果与反例闭环

批次开始日期：2026-10-11。**计划仍为部分完成**。本轮完成六次真实生成尝试，得到五份可运行产物；其中四份原产物的固定业务回放通过，快速型文件产物发现真实缺陷，修复副本复验通过。长期型语音在用户因额度不足关窗时仍处于架构阶段，没有可运行产物。六项均未形成自动交付终态，不能写成六案例全通过。

## 1. 本轮完成的修复

- 核心检查支持分别登记已有逻辑测试和 GUI 测试入口，避免为验收再写聚合脚本。GUI 执行单独记录，不能冒充某条需求的映射；已经声明的场景缺回读仍阻止通过。
- 缺 ASR 入口登记属于可修复的声明缺失，不再误归为等待麦克风许可。核心修复绕过旧阶段“已验证、勿重验”结论，最多两次核心修复；实际缺硬件证据和环境阻塞仍保留待验状态。
- 前缀改名增加宿主固定文件反例。程序自己的 PASS 不能覆盖旧前缀、异目录、越界源/目标等反例失败。只适用于平台两个已支持的 Python Logic 接口；接口不适配明确待验，不推断成功。撤销只在核心需求要求时验证。
- 新增可复用 `file_plan_guard.py`，安装 pywebview 后物化，既有文件不覆盖。快速文件修复副本在后端绑定当前目录/前缀与快照、限制纯文件名及路径；前端输入/扫描变化使旧预览失效，旧异步响应不能恢复可执行状态。
- 测试驾驶固定案例模式取消主动重画草图和自动延长预算；浏览器关闭时拒绝待处理请求并保存失败记录，生成循环结束后停止空等。开测前提醒保留窗口，隔离窗口显示测试标识，结束后通知可关闭。

## 3. 文件缺陷的闭环

原快速文件软件的逻辑自测及三条 GUI 自测可以通过，但 `execute_rename` 信任调用方快照：当前前缀不同、快照指向其他目录、源/目标名含路径时仍发生真实改名。前端非法前缀提示后也保留旧可执行计划。

| 证据 | 原产物 | 修复副本 |
|---|---|---|
| 四个固定计划边界反例 | 0/4 正确拒绝，均有实际文件变化 | 4/4 拒绝且受保护文件不变 |
| 固定 GUI 业务序列 | 未通过；非法输入后执行旧计划 | 最终 3/3 |
| 宿主统一核心门 | failed，覆盖生成方全绿声明 | passed，21 条需求证据及独立 GUI 执行记录 |

修复过程保留了首版修复的扫描竞态失败，以及保护器改变空文件夹错误文案造成的回归；修正后重跑原逻辑、GUI、自测与宿主反例，最终通过。安全的逐项部分成功被允许：受影响源文件、已有目标和目录外文件必须保留，其他无冲突项可以改名。第一版探针要求整批不动而错误拒收长期产物，已按原任务语义纠正。该保护器是执行前条件校验，不声称具备文件操作期间的原子隔离或形式化安全证明。

原演示语音产物仍保留原样：固定音频的一维输入可解码，录音列数组/双声道在旧接口失败；隔离适配副本三个输入通过。新入口使用实际模型解码观测，不以文本模拟代替 ASR。

## 5. 实验边界与剩余工作

1. 第一项 quick 试跑使用旧驾驶器，主动追加了一次草图意见并延长计时；已单列为协议偏离，保留旧启动配置失败记录。其他固定案例去掉该行为。
2. 试跑期间验收接线发生修正，后四案保存启动时的开发主进程 SHA；前两案按 `1aadabf` 构建记录追溯，缺启动 bundle 哈希。不能把六项当作模型、提示词、判定版本全部一致的成功率对照。没有条件一致的改前六次生成基线，不计算降本或生成成功率提升百分比。
3. 原产物业务通过数为 4/5，快速文件修复副本通过后可验证产物为 5/5；自动交付是 0/6。两者回答不同问题。用户中断两项、预算超限一项，不能省略。
4. 长期语音缺产物；最新修复后的完整自动生成链尚未重新进行一组闭环试验。全计划保持部分完成，不继续在额度不足时追加付费生成。
5. 核心两次局部修复已限额；契约/实现阶段的既有续接和子代理重派尚未统一成项目总修复额度。长期任务的多次交接、驱动等待、重复文档核对是主要耗时来源，仍需依据此账本优化。
6. 固定 GUI 三次与已知反例通过不等于统计可靠性、所有界面功能或所有程序类型都得到证明。接口不支持、外部 LLM 产品客户端及全新机器冷安装保留各自待验范围。
