## 保留的真实检查

一个宿主验证入口负责本次必需能力：UI使用实际Python/pywebview窗口的fill/click/expect/restart；无UI命令由宿主直接执行登记的正常Python入口，比较固定输入与实际stdout/退出码。必需能力未覆盖、证据缺失或版本变化仍不能交付。

新链不再强制另写一份自报PASS的CORE_CHECK脚本。已有能力探针继续按需检查；涉及AI或语音时，CORE_CHECK.json只登记真实能力入口。原有核心检查协议继续供历史项目与冻结实验使用。

安全扫描、正常启动、版本核对仍执行。UI交付要求窗口可见、响应、稳定和正常关闭；仅进程存活的降级结果不能通过。真实回放修复了旧Windows启动探针的DWORD_PTR缺失及指针宽度问题，并把窗口匹配限制到本次启动的进程树，不再凭标题选取无关窗口。

原有验证凭据继续使用，绑定目标/代码/环境/宿主实现及GUI、CLI规则；仅完整、仍新鲜的通过结果可复用。记录不能可靠落盘时不释放交付状态。

## 用量和恢复

短任务单、草图、制作、子任务、压缩、物理重试共享同一已授权操作的请求与输出预算。运行时间分段累计，等待用户的正常间隔不计运行时长；崩溃留下的未结算时间保守计入，不能重启清账。目标修订和局部修复不重置额度；已交付后用户提出新的修改才建立新操作，原Pi历史继续保留。

沿用原上限和实际SDK费用账本，没有提高产品额度。请求/输出预算不是人民币保护；金额未配置时不宣称存在人民币硬上限。固定输出回放的请求数不能当作真实模型费用或速度结论。

## 验证边界

这些结果证明当前机制和固定样例可执行，没有证明真实模型已经更快、更省或产物质量更高。原生GUI使用回放明确声明的本机测试解释器，验证其正常入口；它不认证其他项目的依赖环境，更不替代历史生成项目自身虚拟环境资格。

当前真实GUI观察器面向Windows Python/pywebview；无UI观察器面向可执行Python命令及可观察输出，并非任意语言/服务的通用验收器。用例由工作Agent登记、宿主固定并执行；字段关联与执行成功不自动证明语义覆盖充分。外部AI效果、供应商付费连通和真实录音硬件仍需对应证据，缺失保持待验证。

新构建需在用户正常退出并重新启动Bloma后用于新项目；当前运行实例保持原状。回退应停止新任务、保留项目/原生会话/outbox/费用账本，再回退代码；不能用旧版本自动重做副作用或把旧通过套到新产物。
