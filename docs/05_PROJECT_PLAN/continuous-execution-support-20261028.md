# 持续执行、状态分层与按需上下文（2026-10-28）

基线 `sprint2 / 89f795f`。用户要求添加借鉴 Codex 的异步命令、执行/目标分层和按需能力说明，并增强压缩后的工作状态恢复。实现沿用现有 Pi、命令监管、公开上下文工具及交付面板，不接入另一个 Agent 引擎，不增加强制前置阶段。

## 1. 同一命令可持续读取

- `run_command` 新增可选 `yield_ms`（0–30000）：启动一次受管理命令，在初始有界等待后返回 `process_id`，命令继续执行。省略该字段保留同步调用，以兼容已有短命令与工程脚本。
- `read_process` 支持 `since_seq` 和 `wait_ms`（0–30000）。返回新增的有序日志、`next_seq`、截断提示和当前状态，不重新运行命令。UTF-8 使用流式解码；逻辑行完成后统一脱敏，避免凭据被管道分块切开。历史输出有界保留，未完成的长行不会分片作为可见日志发布。
- `write_process` 向本会话实际启动的命令排队发送 stdin，可关闭应用 stdin。仅返回 `bytes_queued`，处理成功必须以实际输出核对。服务、用户进程、其它会话和新宿主无法输入。
- `stop_process`、用户取消和单命令超时终止所拥有的进程树。单命令仍默认 120 秒、上限 300 秒；软件制作整体没有固定 30 分钟限时。所有请求、输出、金额和依赖安装保护保留。
- 命令结束、工具调用返回、模型本轮结束、产品检查和交付分别表达。命令返回 `verification: not_applicable`、`task_completion: unverified`；0 退出码不构成产品 PASS。
- 异步会话不增加模型额度；无新输出时使用有界长等待，避免高频模型轮询。并行做其它独立工作时也继续使用原 process_id，不另启动同一安装或测试。
- 完成条件发现命令尚在运行，会引导读取同一会话。`verify_app` 不冻结或关闭未完成的安装/构建，宿主最终收口也先等已有命令结束。真实等待不会触发普通只读空转计数，也不会清除尚未解决的验收错误。
- 仍使用现有 host-pipe supervisor。EOF 代表宿主失联；旧文件中的 PID 不被接管，读取显示 interrupted。崩溃前未落盘的游标可退回已保留位置并标记输出丢失，不据此重跑命令。stdin 扩展是宿主私有帧协议，未启动 shell，服务行为继续兼容。

示例：

```text
run_command({command:["npm","run","build"],yield_ms:1000,timeout_ms:300000})
read_process({process_id:"返回的ID",since_seq:0,wait_ms:10000})
read_process({process_id:"相同ID",since_seq:12,wait_ms:10000})
```

其中 12 仅为示例，实际使用上次返回的整数 next_seq。

## 2. 执行、最近检查、交付各自展示

- 交付 IPC 返回 `status_view`，面板分别显示本轮状态、最近检查和交付状态，并在流结束时刷新。命令仍运行可显示数量；不改变原有启动/发布授权逻辑。
- 最近检查通过明确标记为“对应记录版本”，不会作为当前工作副本的新通过凭据。损坏记录显示需核对；上次检查运行中但本轮并未验证时显示未完成。
- 活跃索引遇到空闲宿主显示中断；模型或工具结束仍可能是“本轮尚未交付”。长期里程碑待确认与正式交付区分。
- 当前状态进入 running/verifying/verified 时清除当前 error，包括调用方显式带回的旧错误；保留脱敏 `last_failure` 作为历史。运行租约、失败累计、版本与请求账本不清零。
- 修正向导进入制作后失败的外层收尾：日志现在保留 incomplete，不再一边发布 incomplete 事件、一边写 `status=completed`。

## 3. 能力说明按需加载

`read_production_context(capabilities)` 只返回名称、用途、主题和工具元数据；需要时再读取 execution、launch、verification-gui/llm/speech、data-update 或 delivery。目录本身不代表环境已就绪、不扩大当前用户目标，也不会下载资源或调用额外模型。复用现有公开工具，未新增强制 Skills/AGENTS 文件或另一个技能执行框架。

## 4. 续跑与压缩后的工作事实

- `working-state` 返回当前范围/版本、执行/检查/交付状态、未决命令、当前错误与历史失败、累计计量，以及最多 10 条近期工具结果索引。只读最后至多 128 KiB JSONL，不把长源码、命令参数、工具原始输出或凭据重新塞进上下文。
- 工作摘要从实时项目/文件/进程事实生成，不把旧快照当作当前版本；长目标保留 excerpt、feature_count 和完整范围读取入口。摘要有界收缩可选历史，不截断 JSON。
- 请求/输出计量在恢复时读取当前账本，而非上次执行索引的旧计数；不可读时明确不可用，既有准入保护保持权威。
- 软件制作通过 `recoveryContext` 回调接入现有 Pi。开始/续跑及原生压缩后恢复宿主索引；回调不重放工具、不重置预算、不直接调用模型。压缩请求仍走已有受保护通道与账本。
- 摘要是导航事实，不是新需求或产品通过证据。索引不可读时只提示核对公开上下文，不能据缺失数据推断成功。
