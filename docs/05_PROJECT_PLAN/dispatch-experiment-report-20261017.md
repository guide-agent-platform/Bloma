## 1. 阶段结论

本次按用户要求停止扩展实验，保留截止时全部成功、失败、中断与未启动记录。可用于当前统一条件六组比较的是 **L2 quick 的一套完整样本，每组一轮**。M1 为 DeepSeek Flash，M2 为 DeepSeek V4 Pro，固定验证角色 V 为 Flash。其独立业务全通过 **4/6**，原生交付 **5/6**，交付且业务全通过 **3/6**。在这一套有限场景中，直接 Flash 与直接 Pro 均为 14/14，没有观察到混合调度优于最佳同质组的业务质量收益。

这是一份探索性工程实验报告，不能据此给出模型总体排名或显著性结论。L3 当前只运行了两组，均未做外部独立业务评分；L1 quick、L1 longterm 新六组没有启动。难度区间和 quick/longterm 对照尚不完整，不能写成已经完成全面实验。

### 3.3 失败原因及归因边界

- **G11：平台声明门禁失败，业务场景全过。** CORE_CHECK 登记 66 条场景，超过冻结宿主的 64 条上限；反馈未准确指出数量，模型两次修复未解。保留原生失败，不推断“只改这一项就必定全部交付”。
- **G12：导入拒绝反馈存在时序缺陷。** 旧隐藏定时器会提前收起新错误提示。该非法日期导入之后持久化数据与基线一致，没有证据称非法数据已经落盘；后续冲突合并、重复幂等分支没有执行到底。适配器此前的拒绝文案词表和额外横幅要求曾误判，原始记录均保留并透明纠正，重验后仍为真实 13/14。
- **G22：六项业务失败。** 空标题、项目命名、项目删除保护、日期、过期显示和组合筛选。部分后端拒绝被界面报为成功，但有任务的项目没有实际被删除。真实日期控件键盘输入确认 badInput，保存却清空旧合法日期。过期任务已落盘而默认列表漏显，组合筛选的后续路径被此前置问题阻断，不能宣称完整组合路径均已测试。
- **G21：文件选择器的测试接入补充。** drive 模式禁用了系统文件选择器；备份相关两项改在正常启动实例，通过所属实例的 DOM 与所属 PID 的真实文件选择器完成。业务代码、API 和选择结果没有被替换；初次工具定位及重启失败的 pending 记录保留。
- **G12：一次计量写盘异常。** 完整 SSE 返回后结算文件重命名出现 EPERM，并非“尚未发 HTTP”。无活动请求后将责任保守记为 unknown，原金额不减少，再将活动账本迁出 OneDrive。模型自动续接后交付；异常影响耗时与用量完整性。文件占用的具体来源没有查实，迁移只是已执行的环境处置。

## 6. 指标与独立验收方法

| 指标 | 计算或记录方式 | 缺失处理 |
| --- | --- | --- |
| native_ready | 原生 run_outcome=ready | 驱动异常未封口单列 |
| Q | 固定场景通过数 / 场景总数，场景同权重 | 有 pending/error 则 Q=null |
| business_full | 完整 Q=1 | Q 未知则不可判定 |
| end_to_end_success | native_ready 且 business_full | 与两者分别列出 |
| machine_ms | 阶段开始至首次机器终态墙钟时长 | 无终态为 null |
| logical | SDK 逻辑查询次数，含辅助 scope | 不等同 HTTP 次数 |
| physical | 实际传输尝试数，含兼容/错误重试 | 未发 HTTP 的阻断不算传输 |
| Token | 逐查询累加报告用量，保留缓存分类 | 用量缺失仅列已知部分 |
| 费用估算 | 报告用量乘保守峰值费率 | 与 unknown/reserved 分开 |

独立 GUI 验收操作实际渲染窗口中的 DOM 控件，产生输入、变化和点击事件，再核对界面列表、已知输入对应的导出内容、稳定 ID、磁盘数据和真实重启。需要文件选择时使用自有进程及后代的系统选择器。测试数据通过隔离 APP_DATA_DIR 保存，宿主不修改产品业务代码，不直接调用业务 API 写入以替代用户操作。

这属于非盲、样本专属控件适配的有限语义场景测试，不是全部都由物理鼠标点击的端到端可用性测试，也不是全功能证明。适配器错误有保留初始 pending/失败轨迹和修正理由，最终 canonical 场景结果及引用来源都在数据表。早期评分器修订、版本差异和未走到的分支保留说明，不作事后“补成通过”。

## 9. 现有数据能回答与不能回答的问题

当前证据支持：在这一个 L2 任务及固定测试范围内，两种直接实现均可达到业务全通过；交付流程成功与业务正确性会分离；G12/G22 的产品缺陷、G11 的声明门禁和基础设施异常均会影响实验结果。Pro 接手明确诊断的旧代码能够修复案例，但恢复试验不能证明从零实现优势。

当前证据不支持：普遍模型排名、调度策略统计收益、难度上升趋势、完整 quick/longterm 模式效果，或真实平均单任务完整费用。限制包括每条件只有一轮、单一业务任务族、评分非盲且样本专属适配、验证器/宿主协议门禁、供应商缓存与分时价格、运行包/资源演进、未结用量和 L3 潜在窗口干扰。未启动计划不是失败样本，未评分不是零分。
