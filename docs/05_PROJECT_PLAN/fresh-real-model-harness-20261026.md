## 已修复的 harness 问题

1. **草图截断重试重复浪费。** 两次输出达到 8192 token 上限且 HTML 未闭合，重试还回灌整份残片。轻量草图改为干净上下文重试，给出压缩反馈，默认聚焦一个工作区，并注入当前日期避免示例逾期状态过时。仍拒绝残缺或不安全 HTML，没有截断补尾伪造草图。
2. **启动协议不完整，错误不可操作。** `command:"npm start"`、`ui:true` 只得到笼统错误。现在反馈真实字段错误和合法示例；`read_production_context(launch)` 提供协议，overview 同时提供确认的 delivery/distribution/ui，避免做完浏览器程序才发现要求是桌面程序。
3. **启动尚未合法就冻结测试。** `verify_app(script)` 现在先校验启动声明，再冻结脚本；保留输入、断言和业务逻辑的保护。
4. **已有浏览器缺少基地址。** CDP 连接的上下文不接收 `newContext({baseURL})`，导致 `page.goto("/")` 失败。现在相对导航基于实际拥有的本机程序地址解析，沿用原 Page、数据和断言。
5. **裸 Electron 命令导致扫描宿主仓库。** 原解析器保留字符串 `electron`，验收把 `dirname("electron")` 当成当前仓库，误报仓库 `.codegraph` 等链接。现在解析到项目或随 Bloma 提供的真实可执行文件；链接检查报错也包含扫描根目录，没有放开任意链接。
6. **Electron 虚拟文件系统破坏依赖归档。** `.asar` 被当成目录复制，快照随后报 Invalid package。发布快照改用 `original-fs`；真实 Electron 集成回归验证 `.asar` 仍是物理文件且字节哈希一致。
7. **输出预算存在任意比例限制。** 移除“最多减半”的限制，保留最低有效输出、显式思考预算、完整输入预留及人民币硬上限。**仍未实现精确输入 token 预估**，不能把剩余额度等同于可再发请求的金额。

过程中内层 agent 还把宿主 `.codegraph` 链接搬到了备份位置；已核对原目标并恢复。工程命令仍不是操作系统沙箱。本轮没有以移除宿主链接、清空账本或降低验收预期来通过检查。
