## 已落实的改造

| 问题 | 实现与边界 |
| --- | --- |
| 结构化需求、PRD正文与任务重复复述 | 制作system保留全部结构化功能、断言、验证版本与全局约束；完整PRD正文通过只读`read_production_context`按需查询。原默认完整摘要API仍兼容其他阶段。 |
| 执行者拿到与职责无关的大包 | 计划可声明`feature_ids`；宿主在执行者开始和续接时按实际任务所有权生成职责上下文，保留完整相关规则/流程/场景、共享对象与全局约束。编号未知拒绝；没有标注时保留完整结构化范围，不从自然语言猜职责。 |
| 来源追溯数据挤占职责system | 内联包不重复整份sources/coverage；权威读取工具仍提供完整原文与覆盖溯源，需求哈希始终依据完整权威模型计算。 |
| 登记计划后派工再次复制正文 | 派工schema仅引用`task_ids`，平台自动取登记正文；兼容接收到的旧初始task字段不再追加。续接只带新分配任务正文或增量`feedback`，旧任务沿历史继续。 |
| 执行者重复探索平台入口与环境 | 短平台指引明确现成app.py入口、Logic门面、drive/self-check/纠错协议、独立测试数据、现有.venv、接口生产者/消费者和交接事实；调度专注目标、接口、依赖、写入范围与验收引用。 |
| 同一基底给研究者发实现指令 | 领域上下文通过通用委派层的可选`childSystemBuilder`注入，按角色装配；只读角色不再收到实现者写代码/跑脚本职责。通用层不导入桌面领域。 |
| 无关语音/模型/组件说明常驻 | 制作阶段不内联全组件目录；资源由`inspect_project_resources`查询。通用、LLM、语音验证协议分topic读取。 |
| 提示词旧预算与真实资源冲突 | 资源说明来自执行配置，明确脚本默认90秒/可设180秒、累计次数、安装次数、续接不清零；移除quick及longterm任务书中写死的12次说明。 |
| 已有两人后继续创建、依赖状态不清 | 新增只读`experiment_status`，提供实际生命周期、loop结果、交接、任务归属与可续接标记；仍由宿主判定所有权、写入冲突和整轮依赖释放。未真正执行的失败派工不会把计划永久锁死。 |
| 执行工具抛异常绕过源文件回滚 | 审计在异常路径仍检查、恢复越界改动；保留原始样本和错误状态。这是受控执行审计，不是OS进程安全沙箱。 |
| quick中V配置没有真实消费者 | 新六组矩阵登记`production_protocol=v2`，写入条件指纹与汇总兼容性检查。核心、安全、启动检查后实际绑定共同V，进行独立只读源码及宿主证据审阅。旧协议不静默迁移。 |
| V只回一句通过可能假绿 | 必须覆盖所有F、给出证据、无未解决发现，且实际成功读取相关需求、宿主报告及源码；审阅前后源码指纹一致。缺格式、缺读取、源码变更或渠道异常均为unverified。 |
| V发现问题没有返工闭环 | 具体fail发现交原实现者增量修复后复审，最多两次修复，沿同一实验请求/墙钟预算；证据未知不盲目改代码。每次V审阅独立保存证据，不覆盖失败历史。 |
| 交付面板异步旧响应覆盖新产物 | 按请求序号丢弃过期响应，制作转completed也重取数据；加载中不展示旧“缺少LAUNCH”提示。原生驱动交付后刷新并读取稳定面板，另记界面可启动状态。 |

## 验证与实验范围

`read_production_context`保留完整权威资料，不修改用户需求，也不以省token为由截断尾部功能。职责筛选与文本去重改变的是提供方式，模型仍可只读查询全局范围和完整正文。单项职责的内联包去除的是来源/覆盖的重复展现，不删除业务规则。

v2的V是“独立源码和宿主证据审阅”，没有写工具，不替代六项独立GUI业务验收，不直接产生外部Q。V的实际角色路由、请求数、审阅起止和失败/修复都有事件与供应商账本。真实执行者并行仍须由物理请求重叠证明，不能只看容量或已创建人数。

原实验运行副本和冻结home保持不变；新版真实验证须另建运行副本、新home及新版本摘要。共同需求、PRD、UX和六项外部验收沿用已确认L1范围，准备费用、实现/V费用与宿主审阅分开。M1=GLM 5.3 Flash，M2=GLM 5.3，V=DeepSeek Flash；D/E high及原操作保护不因本次改造暗改。
