# 用好现有模型视觉能力

起点 `a0f4f8d`。用户明确当前模型有视觉能力，并同意优先加强Bloma自身看图需求/开发/核对链路，再让生成的软件能以自己的配置调用视觉API。现有OCR保留为本机文字提取组件，不用OCR代替模型视觉。

计划：核对已有附件→Pi→供应商图片水合；修复工程外开发截图无法按所属会话再次查看的缺口；提供产品自有OpenAI兼容视觉客户端；宿主本地探针检查真实图片字节与换图，继续区分协议和真实视觉效果。不新增付费请求、真实账号配置或强制第二模型阶段，不改变交付确认。只本地提交，不push。

## 实现与核对

- 已有链路保留：短任务单整理把input.images及授权材料图传给原请求；Pi使用短imageId，供应商边界才读取base64；Anthropic与OpenAI兼容格式转换已存在。跨轮最多实际携带最近4图、过旧/丢失图显示占位的既有策略不变。核对本地Proma上游 `bf3e98c`，沿用当前存储/传输机制，没有另建视觉执行器或额外模型阶段。
- `view_image({debug_session_id})` 可读取本项目/本会话当前调试截图，解决宿主工程外截图不能用项目path打开的问题。拒绝他人会话、非ready、缺图、旧源码及无来源记录；原 `view_image({path})` 继续限制工程内路径。返回图片短引用、SHA-256、观察源码和版本，标记image_attached_not_reviewed。inspect_app的同类标记同步统一，不把附图写成模型已看过或功能通过。
- 制作指令说明如何用图片附件理解参考图/草图，用inspect_app(include_image:true)或会话截图入口核对可见布局/颜色/反馈，并保留实际操作与数据断言。read_production_context(vision)提供产品视觉调用与验证协议；multimodal区分模型视觉、OCR和音频复用。
- `prepare_software_capability({capability:"vision"})` 受控物化VisionClient与HTTP组件，无额外安装或模型调用。产品以自己的endpoint/model/Key调用OpenAI Chat Completions兼容接口；支持PNG/JPEG/WebP真实字节，最多4图/合计5MiB，图片须来自产品数据目录。拒绝越界、错误签名、缺配置和取消，不把文件名/OCR文字替代成图片。只读图片目录约束不是OS沙箱，文件头检查不保证供应商一定能解码任意畸形图片。
- HTTP组件默认1MiB请求上限保持；产品视觉客户端显式配置8MiB，公共配置最多16MiB，容纳base64膨胀。默认HTTPS公网、DNS固定、来源限制、响应上限与不自动重试行为保留。当前只实现OpenAI聊天兼容协议，不宣称Responses/Anthropic产品客户端、远程图片URL、视频、自动压缩或真实模型质量已验。
- CORE_CHECK的Node llm入口新增可选input:"vision"。宿主生成两张不同的有效PNG，真实调用已登记产品入口，经本地HTTP逐字核对图片data URL、模型与鉴权，增加image_changed反例。视觉模式6次请求/7项，文本旧模式仍为5次/6项；视觉结果有input_kind身份。只返回旧文本探针证据不能放行视觉模式。实际入口仍须产品使用，本机探针不证明真实视觉理解。
