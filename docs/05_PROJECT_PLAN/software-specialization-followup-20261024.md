## 从真实付费样本发现并修复

1. list_files/find显式传`.`不应被当作越界；读取项目根已修复，写入/CAS边界保持。
2. 相同会话、工作目录、命令、数据目录和当前源码的现成服务可复用；不同归属/占用端口继续拒绝，源码变化必须重启。inspect_app可自动连接本会话同地址的已拥有服务，旧后端不会冒充新源码。
3. start_service返回宿主提供的工程外data_dir，并说明不要把业务验证数据写回源码目录。样本自行覆盖到tmp-verify-data导致每次保存都变stale；保留版本失效约束，未忽略任意JSON文件。
4. 请求额度到达、已登记规则且没有取消时，软件流程可以停止模型调用而继续运行免费宿主检查。只有真实核心、安全、启动和版本检查全过才交付；缺规则、错误结果、取消均不能通过，检查失败后不再调用模型修复。历史流程不改。
5. 列表定位提示使用稳定身份/可见文本，避免排序变化后nth-child选错记录。浏览器正常入口由Bloma打开URL，不需要生成服务端spawn浏览器的额外能力。安全扫描未放宽。

## 3元付费窗口结果

使用当前启用的DeepSeek Flash官方渠道。先核对实际模型列表、余额、加密配置及[官方人民币价目](https://api-docs.deepseek.com/zh-cn/quick_start/pricing/)，Windows隔离探针复制匹配的加密Local State，不输出明文Key。费率按高峰价保守预留：输入2元、输出8元、缓存命中0.04元/百万token，上下文上界1048576；请求前预留，未知请求不免费。新授权窗口的持久账本和epoch仅存在于本测试目录，旧全局epoch及旧账本SHA核对未变。预检刷新保留原清单，不能创建新费用额度。

样本是一个固定已确认目标直入software-v1执行的本机浏览器记事本，不含真实需求澄清/草图，不是Proma/Codex对照。最初24次请求、随后16次、再16次，共56次物理请求（含结构化工具资格探针）。三个阶段账本连续，固定请求上限导致中途停止的历史结果完整保留；没有把三个阶段当作独立成功样本。

按供应商已报告token和高峰费率累计计算的保守费用上界为**0.536274元**，低于3元；没有未报告费用请求。它不是供应商精确账单，也不能用暂未更新的余额显示推断免费。56次后停止新增付费调用。

该样本**未实现全自动交付**。一次宿主诊断说明了工程内测试数据造成stale；之后免费宿主检查发现列表位置选择器选错笔记，人工只修正6处selector，固定输入/预期语义SHA核对不变。原失败规则和报告保留。修正后27步GUI通过，但安全扫描继续阻止server.js中的child_process/spawn自动开浏览器代码；总体仍为incomplete，未绕过安全门，也未把界面通过写成完整交付。

该阻断是当前平台能力规则的结果，不能据此认定自动开浏览器本身是安全漏洞；旧服务器规则如何适配软件运行时的必要子进程，还需继续梳理。本轮先明确由Bloma打开浏览器入口，未临时放宽规则来包装成功。
