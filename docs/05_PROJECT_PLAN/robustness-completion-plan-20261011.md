# Bloma 稳健性完成计划

日期：2026-10-11。计划基线：`b9acdd1`，制定前工作树干净。

本文件记录计划与逐批状态，详细验证范围见完成证据。用户已授权执行；历史“待执行”不等于已实现。原产物保持只读，不打包可执行文件。

## 1. 本轮完成目标与边界

目标：让平台对“软件能否完成用户的核心任务”给出与证据一致的判断，并能定位失败、局部修复、复验和解释成本。

完成后应做到：

1. quick 和 longterm 都不能把模拟文本、自测声明、启动成功或旧版本验证，替代当前产物的核心功能实测。
2. 通过、失败、未验证、环境阻塞分别记录；缺少必要执行证据时不能自动宣称完整交付。
3. 旧回忆不重复进入回忆索引，无关项目内容不默认污染当前任务。
4. 语音能力有平台可复用的适配和运行组件，二维录音输入等已知反例进入回归。
5. 项目账本覆盖父流程、子 agent、辅助模型请求、重试和续跑；缺失数据明确标记。
6. 固定小样本能重复验证修复效果，形成可接手的工程证据。

保持当前白色“通透画室”主题，只调整质量状态和失败提示所需的呈现。保留 agent 完成工作的基本工具与当前角色预算，先测量再调整。静态启发式继续作为诊断；严格模式保留，默认不增加一串全量硬门。

不在本轮全面重写编排器、不新增一组评审 agent、不铺开多平台生成、不自动修改历史产物、不强行确定论文创新点、不打包可执行文件。独立验证首先由宿主执行器和固定测试实现，不以增加 agent 数量作为独立性的证明。

## 2. 依据与不确定性

| 事项 | 当前依据 | 本轮如何处理 |
| --- | --- | --- |
| 语音实际输入失败 | 原产物将 `(N,1)` float32 输入传入要求一维波形的接口，真实缓存模型探针复现 TypeError；文本模拟测试绕过 ASR | 确认缺陷，先保留反例，再修平台能力组件并验证隔离产物 |
| 回忆被再次索引 | 当前索引有 71 条以回忆注入块开头的消息，其中 64 条包含嵌套回忆标记；近期工艺项目实际收到旧游戏任务摘录 | 确认污染现象；过滤来源、限制作用域、重建索引，不归因到语音故障 |
| 旧证据复用条件不足 | PQ 在读取当前声明前直接返回旧 qualified；checkpoint 消费主要匹配阶段 | 确认代码缺口；先用变更声明/代码/配置的回归验证，再修复 |
| 必要检查执行异常可被跳过 | quick 冒烟、安全检查等入口有异常返回 null 的路径 | 核对调用端的实际终态；必须执行的检查发生异常时返回未验证/环境阻塞，不能传播为通过 |
| 成本缺乏完整口径 | 阶段遥测主要读取父 loop 用量，子调用和辅助请求未完整汇总 | 补事件和去重账本；不把旧阶段 token 数改称全项目用量 |
| 首次运行和环境风险 | 语音定位器共享用户模型缓存、下载无显式超时；生成依赖有未固定版本 | 风险项，分别验证冷缓存、离线、初始化失败和可恢复性 |

已定位的语音证据见 `voice-demo-failure-and-closed-loop-20261011.md`。本计划不撤销其他案例在既有测试范围内的通过结论。

## 3. 分批执行与交付

各批按顺序完成，必要验证通过后单独提交；不积压全部改动到最后。每批结果更新本计划的状态表，详细执行证据留 `run-artifacts/`。实施前参考本地 Proma 上游的对应模块，记录实际版本、可复用做法和适配差异，不整体 rebase。

### 批 0：冻结基线和最小验证矩阵（预计 0.5 个工程日）

- 记录平台提交、有效提示词来源与内容摘要、模型/渠道、依赖、原产物哈希和已有验证范围。
- 为每个测试明确用户核心目标、真实输入、期望输出、可观察状态和不能替代它的模拟入口。
- 固定三类业务任务：语音转写、记账持久化、批量文件处理。每类有成功、失败及恢复场景；不把所有非核心功能都升为硬门。
- 固定独立断言和输入样本。生成者可以补测试，但不能靠改写期望结果把失败变成通过。
- 核对 quick/longterm 的实际收口、错误和续跑出口，为批 1 确认接线范围。

交付：一份可执行案例清单和基线清单，复用现有运行报告格式，不另建文档框架。

完成条件：能在隔离环境重放已知二维 PCM 反例；能明确指出文本模拟为什么不能证明 ASR；所有后续比较有对应版本和口径。

### 批 1：统一核心功能判定与证据有效期（预计 1–2 个工程日）

入口：`main/desktop/desktop-route.ts`、`dispatcher-finalize.ts`、`provider-qualification.ts`、`phase-checkpoint.ts` 及已有契约/项目状态模块。

- 在已有契约和报告上增加最小能力证据：需求 ID、能力、输入来源、实际执行结果、证据路径、时间和版本指纹。
- quick/longterm 共用核心判定函数，保留不同工作流程。核心缺证据会返回明确原因；非核心缺口以提示呈现。
- 证据强度按具体能力要求判断：真模型 WAV 可以证明模型与适配，不能证明麦克风采集；真实 HTTP 请求不能证明产品 UI 客户端；mock 只覆盖它执行的范围。
- 绑定相关源码、契约/调用声明、模型资源或渠道配置、执行器与样本版本。指纹不含明文密钥；敏感配置只记录不可逆摘要或版本标识。
- 仅在相关输入一致时复用 PQ/checkpoint。必要变化后失效，并记录失效原因；旧记录无指纹按历史未知处理。
- 必要检查异常、超时、缺报告、跳过分别显式返回状态。检查程序自身故障不写成产物业务失败，也不能自动判通过。
- 环境不足时保存产物，显示“已生成，核心功能待验证”等短提示，支持补验与续跑；不反复要求用户确认技术细节。
- 历史 delivered 项目保持原数据，查看时标明历史验证范围；不批量改写历史状态。新执行应用新判定。

交付：共享判定接线、证据结构、版本失效规则、简短状态提示和针对性回归。

完成条件：二维 PCM 失败不能通过完整语音交付；仅文本模拟不能覆盖 ASR；修改相关代码/声明/配置会使旧结论失效；未变化能正确复用；必要检查执行异常不进入通过状态。两种模式都验证上述行为。

### 批 2：清理回忆检索的来源与作用域（预计 0.5–1 个工程日）

入口：`main/agent/loop/session-recall.ts`、消息持久化来源字段及现有回忆测试。

- 明确真实用户消息、助手业务回答、宿主控制、工具输出和回忆注入的来源。回忆注入与控制消息不进入可召回语料。
- 对旧记录识别已知注入块与嵌套回忆；不能仅因普通用户文字提到某个标签就整条丢弃。
- 默认优先当前项目及有明确引用关系的历史；跨项目召回要有任务相关性和可追溯来源，不全局无条件拼接。
- 对回忆块去重、限制长度；检索不到可靠内容可以不注入。
- 使用新索引版本在临时位置重建并验证，再原子切换。保留原会话与可恢复旧索引，不改写历史聊天。

交付：过滤/作用域策略、索引迁移和回归证据。

完成条件：已知嵌套回忆不再被再次索引；工艺任务不默认召回无关游戏摘录；明确引用的旧需求仍能检索；连续重建不增长重复内容；异常退出不损坏原会话。

### 批 3：做实语音组件和首次运行路径（预计 1.5–2 个工程日）

入口：`main/templates/tools/speech_locator.py`、现有语音平台资产/物化入口，以及隔离复制的语音案例。

- 提供生成产物可直接复用的音频适配器：检查维度、声道、采样率、dtype、非有限数和空输入，按明确策略转换为连续一维波形；不随意 flatten 多声道数据。
- 模型准备与预热在录音前完成；录音回调只入队，识别与整理独立执行，队列、停止、取消和重试有界。
- 明确开始、录音、识别、停止、失败和恢复状态；处理设备异常/overflow，避免“显示录音中但已无法输出”。
- 模型目录可配置并支持隔离测试；已有正常缓存兼容。下载设置超时、有限重试、取消和校验，失败不把半文件当正常缓存。
- 记录并固定已验证的关键依赖版本，兼容性基于实测；不宣称单靠锁版本就实现完全可复现。
- 平台提供组件和使用说明，核对任务书确实引用、生成代码确实消费，不能只把文件放进模板目录。
- 原语音产物保持只读；隔离副本验证局部适配和业务链，新生成任务验证平台组件实际复用。

交付：可复用语音组件、资源准备机制、固定样本和隔离产物业务回归。

完成条件：原二维 PCM 反例通过有效适配；固定中文 WAV 经过真模型并在界面显示符合预设要求的文本；静音/非法输入无伪成功；模拟录音回调形状走实际转写代码；连续录音、停止重启和初始化失败后恢复可重复通过。冷缓存/离线/下载中断分别有明确结果和有限结束时间。

真人麦克风测试是单独的硬件证据：获得使用许可后，在目标设备测试采集→上屏→分段→整理；许可或设备未就绪时标为待验证，不用固定 WAV 代替，也不阻止其他批次推进。完整语音交付仍需该核心硬件路径的实际证据。

### 批 4：补齐成本账本，收敛生效规则（预计 1–1.5 个工程日）

入口：`main/desktop/dispatcher-telemetry.ts`、`main/agent/delegation/agent-collaboration.ts`、loop 用量事件、有效默认/覆盖提示词、DELIVERY 与质量报告生成路径。

- 用 project_id/run_id/session_id/父子关联/attempt 标识每次执行，记录父子和辅助模型请求的输入、输出、耗时与状态；重试、取消、耗尽同样留痕。
- 按请求去重，区分 provider 报告值、估算值和缺失值，避免把父汇总与子明细重复相加。用量不全时报告 incomplete，不能填零冒充完整。
- 项目累计和角色分项可以追溯到底层请求。金额只在渠道价格已知且有日期/币种时估算，token 不直接换算成未经核对的收费。
- 先做累计可见性和预算预警。维持现有角色权限/轮数；如需总预算控制，再依据完整账本设置共享限额，并说明在途并发请求可能造成的超出量。
- 建立有效提示词来源清单，把已采用规则收敛到版本化默认；保留用户覆盖，冲突显式提示，不静默覆盖本机文件。
- DELIVERY 的验证状态和证据列表读取宿主执行结果，模型只负责简短说明。展示当前核心结果、已知限制和下一步，不把控制指令展示给用户。
- 不继续为每次失败增加长篇规则；仅保留角色需要的要求，退役重复文档的现行地位并保留历史入口。

交付：完整用量链、口径说明、有效规则清单及报告接线。

完成条件：父/子/辅助请求的已知用量和项目汇总精确对账；重复事件、续跑、取消和缺 usage 各有验证；生成方的全绿声明不能覆盖宿主失败/未验证；默认与覆盖版的实际来源可定位。

### 批 5：固定案例验收与收口（预计 1–2 个工程日）

- 使用批 0 冻结的三类业务任务，每类分别走 quick、longterm，共 6 个新生成任务；固定用户需求、模型/渠道和有效提示词版本。需求只写用户目标，不混入测试锚点或技术实现要求。
- 语音验证真实转写与错误恢复；记账验证操作→DOM→磁盘→重启；批量文件处理验证预览、冲突、不越界改写及恢复。独立断言不由本次生成结果决定。
- 对关键确定性业务路径各重复 3 次；原缺陷反例在隔离副本中检验拒收与修复结果。重复业务回放不等于重新生成 3 轮。
- 外部渠道单独做小规模真实请求与失败路径验证，沿用 PQ 的有限调用范围；不把它混称产品客户端全链通过。
- 先选择一项 quick、一项 longterm 试跑。若判定错误或测试基础设施阻塞，先修问题，再启动其余任务，避免批量烧模型调用。
- 每个新任务初始执行限时：quick 20 分钟、longterm 60 分钟；最多 2 次有明确原因的局部修复。超限保留结果并记 budget_exceeded/待续跑，不无限重启或临时删断言。限时是本批实验边界，不自动改变产品默认预算。
- 运行前固定用量统计范围，记录首次通过、每次失败、续跑和最终结果；报告不能只选择最终成功者。
- 对照优先采用同一隔离产物的旧判定/新判定回放，保留已知反例作为基线。若要声称生成成功率或成本改善，须另做条件一致的基线生成实验；历史成功清单不能替代对照。

交付：同一份结果表、执行日志/截图/业务状态差分、失败反例和最终范围说明。

完成条件：6 个固定任务的核心路径均有独立证据；所有已知反例正确判失败/未验证，局部修复后复验通过且无对应业务回归；关键业务回放各 3 次通过；成本明细可对账。若某项硬件/渠道未测或任务超限，整个计划标为部分完成，列出缺口，不宣称全面成功。

最后执行与改动相关的全量单测、集成、类型检查及隔离桌面检查。只有加载修改后代码确有需要时构建开发产物，不启动/替换用户现有实例，不生成安装包或可执行交付包。最终改动后完成一次必要全量检查，后续仅因新改动或失败重复运行。

## 4. 统一完成标准与指标

| 指标 | 定义与本轮完成标准 |
| --- | --- |
| 误验收 | 系统判完整通过、独立核心场景却失败；本批固定已知反例中必须为 0，报告分子/分母，不外推全平台失败率 |
| 错误拒收 | 独立核心场景通过，却被新判定错误拦截；固定正例必须为 0，环境未验证另列 |
| 核心证据覆盖 | 核心需求及依赖是否有符合范围、版本一致的实际执行证据；6 个任务完成时全部满足，mock 不跨能力计数 |
| 修复闭环 | 首次失败→反例→定位→局部修改→反例消失→原业务及相关回归通过；每步有版本和证据 |
| 回忆污染 | 回忆注入再次入索引、重复嵌套、无关项目召回；固定污染样本中为 0，真实相关引用保持可用 |
| 证据复用 | 输入不变可复用，相关代码/配置/资源变更或缺指纹时不可当当前通过；固定变更矩阵全部满足 |
| 成本 | 每任务父/子/辅助输入输出、已知总量、估算/缺失、运行及验证耗时、修复次数；本批请求可完整对账 |
| 稳定性 | 关键业务回放 3 次、失败恢复、重启/取消均有结果；不把 3 次通过解释成统计可靠性证明 |

不提前承诺成功率提升多少或成本下降多少。只有对照数据支持时才写改善百分比。研究方向在工程闭环稳定后决定：评估能力证据约束、测试选择或反例定位是否有可重复收益，不把普通流程集成直接写成算法创新。
