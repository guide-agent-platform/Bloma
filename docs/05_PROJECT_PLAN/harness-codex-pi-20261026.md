## 标准 Playwright 脚本

现在可在项目内写普通 JS 模块并调用 inspect_app：

```js
export default async ({ page, context, expect, assert, dataDir }) => {
  await page.getByLabel('课程').selectOption({ label: '网络原理' });
  await page.getByRole('button', { name: '保存' }).click();
  await expect(page.getByText('已保存')).toBeVisible();
  return { saved: true };
}
```

调用参数示例：`{ "script": "tests/ui-check.mjs", "timeout_ms": 30000 }`。代码可以使用原生定位、等待、键盘、文件上传下载和断言，不需要把产品控件改造成平台动作表容易点击的样子。旧 steps 接口继续兼容。

用户代码在独立 Node 工程进程内运行，使用现有清理过的工程环境，不导入 Bloma 主进程，也不注入平台模型密钥。绑定只来自当前项目/会话拥有的浏览器，CDP 只监听回环地址。脚本必须是当前项目内的真实 JS 文件；工程外文件或跳转到外部的路径不接受。超时或脚本失败只终止脚本执行，应用会话可以继续使用。

Electron 与浏览器都通过拥有的 Chromium 上下文操作；下载目录在隔离开发数据下。浏览器状态随正常暂停保存、恢复时读回。这里提供的是工程能力及所有权检查，不是操作系统沙箱，也不宣称支持任意浏览器、原生应用或所有 CDP 低保真边缘行为。

## 观察检查点与选定文件恢复

成功的实际开发观察、无本版本页面异常、且观察前后源码一致时，保存源码检查点。源码版本相同复用清单，内容按摘要去重；不反复整份复制依赖。检查点只记录观察过的版本，不能当作独立业务验收凭据。

采用与验证指纹相同的文件选择规则，排除 Git、依赖、运行环境、宿主展示输出及 data/等目录中的非代码数据。开发数据 APP_DATA_DIR 保持在工程外。快照每份最多 3000 文件、32 MiB，单文件 8 MiB；超出或复制期间变化时返回 checkpoint_error，不阻断普通开发观察，也不伪造可恢复状态。

inspect_app 的 read 返回 current_source、source_checkpoint 和源码差异。restore 需要检查点 ID、刚读到的当前版本及明确的 paths；不根据旧观察盲目覆盖当前文件。修改前停止本任务拥有的开发实例并再次核对版本；先保存所有被覆盖的原始字节与恢复日志，再逐文件原子替换。中间失败时恢复已替换文件，失败证据仍保留。

它不会自动删除新增文件或重置整个工程，不操作依赖和独立开发数据。只有选定文件被还原；complete_source_match 明确报告是否与整个检查点一致。恢复不产生 PASS，仍应重新运行测试。新版本观察失败时保留旧检查点，进程关闭后也可以继续查找与恢复。
