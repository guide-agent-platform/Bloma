# Bloma Token 用量监测

在 Bloma 桌面应用中打开「设置 → Token 用量」。内置面板由 Electron 主进程提供用量和价格数据，随应用构建，无需 Python。首次进入面板时尝试同步官网价格。

## 独立浏览器版

也可在 Bloma 仓库根目录启动独立版，使用 Python 3.10 或更高版本，无需安装 Python 依赖。

```powershell
python ".\token monitor\server.py"
```

打开 [本机面板](http://127.0.0.1:8766/)。服务每 5 秒读取 Bloma 的本机账本和会话记录，默认使用 `PROMA_HOME`，未配置时使用 `~/.proma`。

```powershell
python ".\token monitor\server.py" --home "C:\path\to\proma-data" --port 9001 --offline
```

`--offline` 跳过启动时的官网请求，仍可从价格面板手动刷新。服务仅监听 IPv4 回环地址。账本和会话文件只读，刷新价格成功后只写入 `PROMA_HOME/token-monitor/pricing-cache.json`。摘要由本机提取用户消息和回复片段，无需模型调用。

## 查询口径

- 项目与起止时间共同筛选请求。按请求开始时间纳入统计，结束时间包含所选整分钟，时间采用浏览器时区。没有模型调用的用户消息也可在逐轮视图中找到。
- 趋势、工作流阶段和供应商／模型三种图表使用同一批筛选结果。勾选项只改变图表展示的 Token 类别。缓存读取、缓存写入、非缓存输入和输出分别统计，全部输入为前三项之和。
- 每次模型查询只累计账本 `query_finished` 中供应商上报的用量。失败重试和缺失用量会标出来，空缺字段显示破折号。
- 新账本记录可标记阶段及关联的对话轮次。历史阶段按已知运行角色映射，缺乏依据时显示「未归类」。缺少明确轮次 ID 时尝试关联请求开始前两分钟内、同一会话的最近用户消息，并显示「轮次关联为推断」。同一运行的后续请求沿用首次关联，无法关联的请求单独显示。
- 阶段包含需求、界面、制作、验证、交付。Bloma 的宿主检查、打包及发布可以在没有模型请求的情况下完成，相应阶段显示 0 Token。

## 价格

在线读取 [OpenAI](https://developers.openai.com/api/docs/pricing)、[Anthropic](https://platform.claude.com/docs/en/about-claude/pricing)、[DeepSeek](https://api-docs.deepseek.com/quick_start/pricing/) 和 [Google](https://aistudio.google.com/docs/pricing) 的公开文本费率。启动时尝试同步，也可以在「模型价格」中手动刷新。按供应商和模型标记来源与日期。官网不可访问或解析失败时使用最近成功的本机缓存，再回退到随仓库附带的快照。OpenAI 部分旧模型来自参考项目 2026-08-24 的快照。

估算按当前公开费率和 [Frankfurter 参考汇率](https://frankfurter.dev/) 换算成人民币，显示两到三位小数，正数低于 0.001 元时显示「<¥0.001」。模型价格表会标明汇率日期，断网时使用最近汇率缓存或随附快照。DeepSeek 按每次请求的开始时间选择峰谷费率，2026 和 2027 年节假日依据国务院放假通知。峰谷时段无法确认时才显示区间。长上下文、特定缓存保留期限、工具收费、订阅套餐和自定义渠道实际费率以供应商账单为准。

## 请求审查

1. 选中项目和时间范围，点击「查询用量」。切换「工作流阶段」「制作细分」或「请求结果」查看图表。
2. 在「请求审查」点击「检测 Ollama」，可以选择已安装的本地模型。自动选择优先使用 Qwen3.5 9B，也支持 Qwen3 14B 等本地模型。模型由 Ollama 提供，地址为 `127.0.0.1:11434`。
3. 在「会话」选择某个主会话，预筛和审查只处理该会话及其子 Agent 的调用，时间筛选也同时生效。选择「全部会话」时，按当前项目和时间范围审查。默认「仅审查待判定」处理有线索但用途或结果未明确的请求，以及仍需解释的实际失败。「全部未审查请求」也会处理规则已判定且有证据的请求。没有可供判断的回复或工具证据时，进度会计入「证据不足，跳过」。仅有中途重试的请求无需补失败摘要。后台按启动时的范围逐批运行。离开面板后任务继续，返回即可查看进度。点击停止会先处理完当前批。退出 Bloma 或停止 Python 服务会结束后台任务。
4. 每批结果保存到 `PROMA_HOME/token-monitor/audit-v1`，两版可复用。已审查且证据未变的请求沿用已有分类；缺少失败原因摘要的记录会补写摘要。请求详情会保留可读的原回复，展开「技术详情」可查看可读的工具输出。
5. 在制作模块表查看总 Token、已完成、失败和证据不足。部分完成有用量时会显示对应列。展开失败列表或逐轮明细，可查看目的、结果、工具参数摘要与失败返回。

审查前的预筛统计随筛选和审查范围更新，无需调用 Ollama。审查时显示当前会话、批次和等待时间，并保留本轮最近 24 个批次的输入字节数、耗时和错误。批次上限为 8 条调用，按实际发送的 UTF-8 消息长度提前拆批。

批次超时、返回格式错误或缺少有效结果时，已成功的结果会保存，失败的记录拆成更小的批次，最多自动重试一次。再次失败的记录标记为「未知错误」，其他批次继续。请求详情会显示最近的审查错误。默认审查跳过证据未变的「未知错误」记录，手动选择「仅重试未知错误」可只重新审查这些记录。Ollama 不可用或无法保存缓存时，当前审查会停止并显示错误。

新请求通过账本中的工具调用 ID 关联执行结果。老请求使用同会话中唯一接近请求结束时间的助手记录，页面会标出历史时间匹配。文件路径和工具类型明确指向某个模块时优先使用这些分类证据，同时展示模型判断。日志里的工具失败、取消和响应截断优先决定失败或部分完成；对缺乏回执的请求保留证据不足。本地模型判断只用于审查，不参与 Bloma 的正式验收。

一次请求的 Token 归到一个类别，跨模块动作可以归入「跨模块」。一次请求同时有成功和失败动作时，其用量归入「部分完成」。请求失败用量只累计已上报 Token。没有单独计量的传输尝试只按次数展示。

审查前在本机按主会话归并各轮和各子 Agent 的调用。每批来自同一会话，最多审查 8 次调用。长会话优先沿轮次边界分批，单轮超过上限时再拆分该轮。每批发送相关轮次的用户目标、其他轮次的简短上下文以及待审请求各自的回复和工具证据。项目与时间筛选决定哪些调用需要返回结果，同一会话的其他轮次可以作为背景。审查结果和 Token 统计仍以每次调用为单位。
