# 按实际证据验证软件

1. 先核对本轮已确认的需求与预期。已有项目保留原测试及失败基线；独立验收设计启用时用 `read_production_context` 的 `independent-design` 读取冻结输入与断言，不为通过检查改写预期。
2. 用 `read_production_context` 的 `launch` 核对正常入口。`LAUNCH.json` 使用 `schema_version: 2`，`command` 为参数数组。一次性命令使用 `mode: "command"` 并省略 `ui`；图形应用按真实入口选择 `browser`、`electron` 或 `webview`，不填写 `ui: "none"`。
3. 命令行程序实际运行确认的输入并检查输出/退出码；图形程序使用 `inspect_app` 或 `verify_app` 走关键用户路径，查看真实截图，核对数据写入与重开读回。仅 DOM 存在、组件准备或进程启动不等于功能完成。详细协议按需读取上下文，不另造验收接口。
4. 失败先分类：产品行为不符、测试定位/适配错误、运行资源缺失。修复对应原因后以同一业务输入和预期复测。重复相同失败且无新证据时说明具体阻塞，不空转或自报通过。
5. 审阅发现、宿主检查及最终交付由现有台账和门禁裁决。没有执行的外部服务、付费模型、真实设备或干净机器检查须明确未验证，不把模拟响应当作真实服务成功。
