# 修改与恢复已有软件

1. 用 `read_production_context` 的 `working-state` 和 `diagnostics` 读取当前目标、版本、未完成操作和失败证据。点选反馈中的组件定位是查找线索；若带有试用版本，以用户看到的版本解释意见，核对当前源码差异，不把当前文件误当旧版本。
2. 用 `inspect_repository` 和按需文件读取定位相关实现、测试及数据格式。先实际复现问题或记录无法复现的条件；不要扩充用户没有确认的功能，也不要因为测试脚本失效而修改正确的产品行为。
3. 在现有工程中做必要修改，保留原数据和未涉及的行为。测试使用 `APP_DATA_DIR`；数据格式变化时检查旧数据读回。仅操作自己的受管进程，未完成命令用 `read_process` 接续，不重复启动。
4. 界面改动通过 `inspect_app` 的实际截图和操作核对；可用标准 Playwright 脚本定位用户指定控件。依据确认预期设计验证，用 `verify_app` 或当前登记的 GUI/CLI 检查复测。工具协议按需读 `read_production_context`，不要猜参数或使用其他仓库的 Sprint 脚本。
5. 本机受控验证、真实外部效果、交付状态分别报告。通过已有宿主审阅及交付门后才称为交付；缺少凭据或资源时保留现场并说明边界，不借用平台密钥或另行付费。
