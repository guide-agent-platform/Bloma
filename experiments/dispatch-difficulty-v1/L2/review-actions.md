# L2 固定操作模板（方法试点，非完整模型比较）

生成样本前保存本文件、request.md、suite.json 和评分规则的 SHA-256。评审为 Codex，知道平台修复背景，不宣称盲法。所有操作走真实 GUI；DOM/导出仅用于读回，不能直接调用业务方法制造操作结果。每项记录动作、预期、实际、证据及 passed/failed/pending；完整分母为 14。有 pending 时 Q=null。

日期 T 为测试开始时的中国本地日历日期，保存时区及 T-1/T/T+1；跨午夜重做日期项。每个场景使用独立 APP_DATA_DIR，同名对象按位置与操作历史标为 A/B，必要时从导出读取稳定 ID，不按标题合并。

| id | 操作和预期 |
|---|---|
| add-trim | 建合法项目，新增 `  同名任务  `；显示 `同名任务`，关闭并重开仍无首尾空格。 |
| empty-rejection | 有一条合法任务且清空所有筛选；分别新增空串、三个空格，原有完整列表与计数保持 1。 |
| toggle-isolation | 同项目新增两条 `同名任务`，标为 A/B；只完成 A，B 未完成；取消 A，B 仍未完成。 |
| filters | 独立目录两条任务，一条完成；全部/未完成/已完成分别 2/1/1；切换不改变状态。 |
| delete-isolation | 两条同名任务 A/B，完成 B；只删 A，B 与完成状态保留；重启核对。 |
| restart-persistence | 三条任务；修改 A 标题为 `  改名后  `，完成 B，删除 C；关闭所有该产物进程重开，A=`改名后`、B 完成、C 不存在。 |
| project-names | 新增 ` 工作 ` 应为 `工作`；拒绝空名、空格名及 `工作`/` 工作 ` 两种重复，项目与原任务不变。 |
| project-assignment-move | 工作/生活两项目各建同名 A/B；A 高优先级、T+1、已完成；只移 A 到生活；源空、目标两条，A 字段与 B 状态均保留，计数同步。 |
| project-delete-guard | 项目内有 A 时删除应明确拒绝且不丢数据；移 A 到另一项目后，删除原空项目成功，A 与其他项目保留。 |
| priority-calendar | 建低/中/高三条，分别无日期、有效闰日 2028-02-29、T+1；重启字段保留；尝试 2026-02-30 和非闰日 2027-02-29，不能新增非法日期或改坏已有日期。浏览器日期输入的原生拒绝也计合法拒绝，但须记录实际值。 |
| overdue-boundaries | A 未完成 T-1、B 未完成 T、C 未完成 T+1、D 已完成 T-1；过期列表仅 A，数量 1；清除筛选恢复四条。 |
| combined-filters | 工作项目 A=`Alpha`/高/未完成/T-1；B=`ALPHA`/高/未完成/T；C=`Alpha`/低/未完成/T-1；D=`Alpha`/高/已完成/T-1；生活项目 E=`Alpha`/高/未完成/T-1；工作项目 F=`Beta`/高/未完成/T-1。搜索 `aLpHa`+工作+未完成+高+过期，应仅 A，计数 1；清空应恢复六条。移 A 到生活后原组合为 0；改 C 为高后原组合为 C、计数 1。 |
| backup-roundtrip | 独立目录两项目，含同名任务及不同状态/优先级/无日期与合法日期；真实导出，保存文件哈希；新空目录真实导入，逐字段与任务独立数量一致，重启一致。 |
| import-atomic-idempotent | 以产品真实导出的合法格式为基准，不指定模型未承诺的字段名；预先封存语义变换：删除一条记录的必需标题、给一条记录非法日期、同 ID 改内容制造冲突，各另附一条有效新记录。每份导入应整份失败，有说明，导出前后语义状态不变。合法备份重复两次合并，保留备份外任务，不增重复、不合并同名；重启核对。 |

适配仅允许寻找语义相同的控件、按导出实际字段编码上述固定数据，不改变操作与预期。缺入口为产品缺功能；有入口但驱动无法操作记 pending，不能直接业务 API 绕过。文件对话框可受控提供路径，但必须经真实导入/导出按钮触发产品处理。每个破坏性导入用不同文件且留存原始文件、变换脚本与哈希。

体验五维按 dispatch-scoring-rubric-20261014.md 另列，每项必须有真实观察。若没有实际截图，不评视觉美观。试点后发现的清单问题先记录，再统一修订下一版，不回改已经冻结的本次标准。
