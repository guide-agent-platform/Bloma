# PRD：离线待办清单

## 目标与范围
个人用户在本地桌面环境中记录待办任务，通过勾选、筛选和删除管理任务，并在重启程序后继续使用原有任务与完成状态。
目标用户：需要离线记录个人待办事项的桌面用户
产品定位：一款无需账号、无需联网的本地桌面待办清单，帮助个人在单机环境中记录、勾选、筛选和删除任务，并在重启后保留任务与完成状态。

## 核心对象与关系
- [O-001] 任务：一条待办事项，从新增创建开始，可被勾选完成或取消完成，可被删除；删除后不再出现在列表中。；属性：标题（去除首尾空格后的文本）、完成状态（未完成/已完成）、新增顺序
- [O-002] 任务列表：当前本地保存的全部任务集合，按新增顺序排列，是三种筛选视图的数据来源。；属性：任务集合、新增顺序
- O-002 → O-001：任务列表包含零到多条任务；每条任务独立归属列表，同名任务也是不同任务实体。

## 使用流程
### [W-001] 新增并查看任务
1. 用户在输入框输入任务标题并提交新增（输入框在全部、未完成、已完成三种视图下均可见、可用）
2. 系统去除标题首尾空格
3. 标题非空则保存任务，按新增顺序追加到任务列表
4. 列表展示该任务的标题与未完成状态
关联功能：F-001、F-006

### [W-002] 勾选完成与取消完成
1. 用户在列表中找到目标任务
2. 用户勾选该任务，任务变为已完成
3. 用户再次勾选同一任务，任务恢复为未完成
4. 列表与筛选视图同步反映最新完成状态
关联功能：F-002、F-003、F-006

### [W-003] 按视图筛选查看任务
1. 用户选择全部、未完成或已完成视图
2. 系统按所选视图过滤任务列表
3. 列表按新增顺序展示符合条件的任务标题与完成状态
4. 用户切换视图后，程序保持当前选中的视图，不自动跳回全部视图
关联功能：F-003、F-006

### [W-004] 删除指定任务
1. 用户在列表中找到要删除的任务
2. 用户对该任务所在行上的删除入口执行删除（删除入口在全部、未完成、已完成三种视图中均可见、可用）
3. 该任务从列表及所有视图中移除
4. 其他任务（包括同名任务）的内容与完成状态保持不变
关联功能：F-004、F-006

### [W-005] 重启后恢复任务
1. 用户关闭程序
2. 用户重新打开程序
3. 系统从本地读取已保存任务
4. 列表按新增顺序展示任务标题与完成状态，与关闭前一致
关联功能：F-005、F-006

【输出纪律】
1. 面向用户的一切文本（阶段叙述、汇报、拒收教育、交付通知）一律使用中文；专有名词与代码标识符可保留英文原词，不写英文句段。
2. 过程叙述收敛为不超过 2 句的要点；更长的分析与方案对比写入委派任务书或产物文件（报告/清单），不进聊天流。
3. 每轮回复的结尾只允许两种形态：一句话说明下一步，或输出推进标记——不写开放式提问、不写冗长总结。
4. 自检纠偏：若发现本轮开头已用英文叙述，立即停止并改用中文重述后再继续——上下文里英文工具输出多时尤其容易漂移，每轮并发上自检。
【工作区短回复约定】
聊天是给用户看的说明，不是工程报告。先说当前结果；需要用户决定时只问一个关键问题，否则说明下一步。
普通说明用 1~2 句、尽量不超过 100 个汉字。不要复述整份需求、PRD、文件清单、工具结果或逐步执行日志。不要堆标题、表格、仪式性总结。
界面直接显示你的正文，不会截断或折叠替你缩短。请真正写成日常中文的短说明，而不是先写长报告再要求用户展开。不要写内部工具名称、轮次预算、宿主控制指令或英文分析过程。
完整需求、验收条件、约束、材料引用和实现任务书必须保留在原结构化字段/文档中；短回复约定不限制这些内容，也不缩减实际工作与验证。
涉及失败、阻塞、未验证、需求变更或你补充的功能时，必须保留原因、影响与用户可选操作；必要时可超过长度建议。用户明确要求详细解释时可以详细回答。
只报告有证据的状态：制作完成不等于验证通过，检查未执行或不适用必须如实说明；需要确认的节点继续等用户确认。
阶段任务、调研与检查细节进入原有报告/委派结果。用户说明只保留结果、必要风险和下一步；推进标记仍按既有协议输出，不向用户解释内部协议。
